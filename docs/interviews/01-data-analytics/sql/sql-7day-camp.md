## 使用说明

这套训练按 Day 1 到 Day 7 递进，建议每天按“基础题 -> 进阶题 -> 复盘”完成。

- 先独立写 SQL，再看参考答案
- 每题先定义统计对象和口径
- 做完检查：筛选条件、分组维度、连接关系、是否去重

统一业务表与字段说明见：[`SQL 复习讲义（业务分析向）`](/knowledge/01-data-infrastructure/sql/sql-review-handbook)

## Day 1：单表查询基础

目标：熟悉 `SELECT`、`WHERE`、`ORDER BY`、`LIMIT`

### 题目清单

1. 查询 `users` 所有字段
2. 查询 `2025-03-01` 之后注册的用户 `user_id`、`register_date`
3. 查询上海用户的 `user_id`、`city`、`channel`
4. 查询渠道为 `douyin` 或 `xiaohongshu` 的用户
5. 查询金额大于 `200` 的已支付订单
6. 查询 `beauty` 类目商品并按价格降序
7. 查询最近 `10` 条访问记录
8. 查询价格在 `50` 到 `100` 之间的商品

### 自查点

- 是否正确使用 `IN`、`BETWEEN`、`LIKE`、`IS NULL`
- 是否理解 `LIMIT` 要配 `ORDER BY`
- 是否知道 `WHERE` 里不能直接用聚合函数

## Day 2：聚合与分组

目标：熟悉 `COUNT`、`SUM`、`AVG`、`GROUP BY`、`HAVING`

### 题目清单

1. 统计总用户数
2. 统计每个城市注册用户数
3. 统计每个渠道注册用户数并降序
4. 统计每天访问次数
5. 统计每天 `DAU`
6. 统计每天支付订单数与支付金额
7. 统计每个类目的商品数和平均价格
8. 统计每个用户支付订单数
9. 查询支付订单数 >= 3 的用户
10. 统计每个城市用户平均订单金额

### 自查点

- `COUNT(*)` 与 `COUNT(DISTINCT user_id)` 区别
- `WHERE` 与 `HAVING` 的执行阶段区别

## Day 3：多表连接

目标：掌握 `INNER JOIN`、`LEFT JOIN`、`ON`

### 题目清单

1. 每笔订单关联用户渠道
2. 每笔订单关联商品名称和类目
3. 每个用户的注册城市和访问次数
4. 每个用户的支付订单数
5. 有访问但从未下单的用户
6. 每个渠道支付订单数
7. 每个类目支付金额总和
8. 每个城市支付用户数
9. 浏览过 `detail` 且有支付订单的用户
10. 没有访问记录的注册用户数

### 自查点

- 是否先确定主表（要保留全集的对象）
- 是否注意一对多连接导致的重复计数

## Day 4：条件统计与业务表达

目标：熟练使用 `CASE WHEN` 表达业务口径

### 题目清单

1. 每天总用户数与付费用户数
2. 城市为空统一归类 `unknown`
3. 按支付订单数给用户分层：未付费 / 轻度 / 重度
4. 各渠道男性用户数与女性用户数
5. 按天统计金额分层人数（<100、100-299、>=300）
6. 各城市下单用户数与未下单用户数
7. 每天访问 `cart` 且支付成功的用户数
8. 用户标签：注册 7 天内是否完成支付

### 自查点

- 能否把业务定义直接转为可执行条件
- 能否在聚合函数中正确嵌套 `CASE WHEN`

## Day 5：CTE 与窗口函数

目标：解决“每组第一 / Top N / 排名”问题

### 题目清单

1. 每个用户金额最高的一笔支付订单
2. 每个类目最贵商品
3. 每个城市注册最早用户
4. 每个用户最近一次访问页面
5. 每个类目支付金额 Top 3 商品
6. 每个用户累计支付金额及全局排名
7. 每天支付金额最高订单
8. 每个用户第二笔支付订单

### 自查点

- `ROW_NUMBER()` 与 `RANK()` 的语义区别
- 是否正确写出 `PARTITION BY` 与组内排序

## Day 6：岗位场景专项

目标：把 SQL 题映射为真实业务指标分析

### 数据分析方向

1. 每天 `DAU`
2. 每天支付转化率
3. 各渠道首单转化人数
4. 各类目 `GMV` / 支付订单数 / 支付用户数
5. 指定注册 cohort 的次日留存
6. 复购用户数（支付订单数 >= 2）

### 产品经理方向

1. 注册 -> 详情 -> 加购 -> 支付 漏斗人数
2. 各页面 `UV` 与最高页面
3. 新老用户支付转化率差异
4. 访问 `detail` 后 3 天内支付用户数
5. 各渠道首周留存用户数
6. `cart` 页面访问到支付转化率

## Day 7：综合题与面试表达

目标：从“会写 SQL”升级到“可解释、可复盘、可沟通”

### 综合题

1. 各城市近 30 天支付金额 Top 3 用户
2. 各渠道注册用户 7 天内支付转化率
3. 各类目复购用户平均支付金额
4. 连续 3 天有访问记录的用户
5. 每天新增、活跃、支付用户数
6. 首单发生在注册 3 天内的用户占比

### 面试口头题

- `WHERE` 与 `HAVING` 区别
- `INNER JOIN` 与 `LEFT JOIN` 区别
- 为什么连接后行数可能增大
- `COUNT(*)`、`COUNT(1)`、`COUNT(col)` 区别
- `ROW_NUMBER()` 与 `RANK()` 区别
- 如何分析某页面转化差

## 建议复盘模板

每题写完后，用 4 句话复盘：

1. 这题核心考点是什么
2. 分母和分子分别是什么
3. 是否有重复计数风险
4. 如何向面试官解释这条 SQL

## 练习建议

- 每天至少完成 6 到 10 题
- 对错题建立自己的“口径清单”
- 二刷时优先训练口头解释能力

需要完整参考答案时，可结合现有题库页：[`SQL 与数据库习题`](/interviews/01-data-analytics/sql/sql-exercises)。
