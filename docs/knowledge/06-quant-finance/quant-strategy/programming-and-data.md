### 1. Pandas 核心操作（防未来函数与清洗）

面试官常让你手写或口述 Pandas 代码。

- **防止未来函数（Shift）**：  
  计算信号时，只能用昨天收盘前的数据来决定今天的交易。shift可以把信号往后诺懿航
  ```python
  # 错误：用今天的信号乘以今天的收益率（未来函数！）
  # df['strategy_ret'] = df['signal'] * df['daily_return'] 
  
  # 正确：昨天的信号决定今天的仓位
  df['strategy_ret'] = df['signal'].shift(1) * df['daily_return']
  ```
- **去极值（MAD法，Median Absolute Deviation绝对中位差）**：
  比 `3-sigma` 更稳健，因为中位数不容易被极端值拉动。
  
  `3-sigma` 法的思路是基于**均值**和**标准差**设上下界。若样本为 `x_1, x_2, ..., x_n`，则：
  $$
  \mu = \frac{1}{n}\sum_{i=1}^{n} x_i,\qquad
  \sigma = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(x_i-\mu)^2}
  $$
  
  当阈值取 `k=3` 时，上下界为：
  
  $$
  Upper = \mu + 3\sigma,\qquad Lower = \mu - 3\sigma
  $$
  
  超出区间的值会被截断到边界上。
  
  `MAD` 法则先算**中位数**，再算**绝对中位差**：
  
  $$
  m = \operatorname{median}(x_1, x_2, \dots, x_n)
  $$
  
  $$
  MAD = \operatorname{median}(|x_i - m|)
  $$
  
  为了让 `MAD` 在正态分布下和标准差口径更接近，常乘上 `1.4826`：
  
  $$
  \hat{\sigma}_{MAD} = 1.4826 \times MAD
  $$
  
  当阈值取 `k=3` 时，上下界为：
  
  $$
  Upper = m + 3 \times 1.4826 \times MAD,\qquad
  Lower = m - 3 \times 1.4826 \times MAD
  $$
  
  因为极端值会明显影响均值和标准差，但对中位数影响较小，所以金融截面数据里通常认为 `MAD` 比 `3-sigma` 更稳。
  ```python
  def mad_filter(s, n=3):
      median = s.median()
      mad = (s - median).abs().median()
      # 1.4826 是为了让 MAD 在正态分布下等效于标准差
      upper = median + n * 1.4826 * mad
      lower = median - n * 1.4826 * mad
      return s.clip(lower, upper)
  ```
- **标准化（Z-score）**：
  将因子值转化为均值为0，标准差为1的分布，方便不同因子相加。
  ```python
  def z_score(s):
      return (s - s.mean()) / s.std()
  ```

### 2. SQL 窗口函数（截面数据处理神器）

量化中经常需要“每天选出因子值最大的前10个品种”，这必须用窗口函数。

- **考点：计算每天每个品种的截面排名**
  ```sql
  SELECT 
      trade_date, 
      symbol, 
      factor_value,
      -- 按日期分组(PARTITION BY)，按因子值降序排列(ORDER BY)
      RANK() OVER(PARTITION BY trade_date ORDER BY factor_value DESC) as cross_rank
  FROM factor_table;
  ```
  
  这里的 `OVER(...)` 是**窗口函数的核心语法**，可以理解成：
  “函数不是对整张表直接算一个总结果，也不是 `GROUP BY` 后把多行压成一行，而是**先定义一个窗口，再在窗口内部对每一行做计算**。”
  
  这句里：
  
  - `RANK()`：排名函数，用来给每一行打名次。
  - `OVER(...)`：告诉 SQL，“这个排名要在什么范围内、按什么顺序来算”。
  - `PARTITION BY trade_date`：先按 `trade_date` 把数据分成一个个小组，也就是“每天各算各的”，不同日期之间互不影响。
  - `ORDER BY factor_value DESC`：在每一天这个小组内部，按因子值从大到小排序，因子值越大，排名越靠前。
  
  这个查询的执行逻辑可以理解为 3 步：
  
  1. 先从 `factor_table` 里取出每一行的 `trade_date`、`symbol` 和 `factor_value`。
  2. 再按 `trade_date` 分组，例如把 `2026-04-01` 的所有品种放一起、`2026-04-02` 的所有品种放一起。
  3. 在每个日期组内部，按 `factor_value DESC` 排序，然后用 `RANK()` 给出名次，生成新列 `cross_rank`。
  
  它和 `GROUP BY` 的区别很重要：
  
  - `GROUP BY` 会把多行压缩成一行，例如“每天的平均因子值”。
  - `OVER(...)` 不会丢掉原始行，而是在**保留每个品种原始记录的同时**，额外计算一个“它在当天排第几”的结果。
  
  例如某一天的数据是：
  
  - `A`：`factor_value = 9.5`
  - `B`：`factor_value = 8.1`
  - `C`：`factor_value = 8.1`
  - `D`：`factor_value = 6.0`
  
  那么排序后，`RANK()` 的结果会是：
  
  - `A -> 1`
  - `B -> 2`
  - `C -> 2`
  - `D -> 4`
  
  也就是说，`RANK()` 遇到并列会并列排名，后面的名次会跳号。如果你想让并列后名次连续，可以用 `DENSE_RANK()`；如果你希望强行不并列、按出现顺序依次编号，可以用 `ROW_NUMBER()`。
  
  所以这条 SQL 的本质就是：**对每天的所有品种做一个截面排序，并把每个品种当天的名次写回原表结果中。**
- **考点：计算每个品种过去5天的移动平均收益**
  ```sql
  SELECT 
      trade_date, symbol, close_price,
      AVG(close_price) OVER(
          PARTITION BY symbol 
          ORDER BY trade_date 
          ROWS BETWEEN 4 PRECEDING AND CURRENT ROW
      ) as ma_5
  FROM price_table;
  ```

#### 1. Pandas 核心结构与常见操作

- **Pandas 常见数据结构**：
  - `Series`：一维带索引数组。
  - `DataFrame`：二维表结构，最常用。
  - `Index`：行列标签对象，本质上也是 Pandas 的核心结构之一。
- **Series 常见数据类型**：
  - 数值型：`int64`、`float64`
  - 布尔型：`bool`
  - 字符串/对象：`object`、`string`
  - 时间型：`datetime64[ns]`、`timedelta[ns]`
  - 类别型：`category`
  - 也可能见到空值兼容类型，如 `Int64`、`boolean`
- **拼接多个 DataFrame 的函数**：
  - 主要用 `pd.concat()`
  - 常见参数：
    - `axis`：按行还是按列拼接
    - `join`：`inner` 或 `outer`
    - `ignore_index`：是否重置索引
    - `keys`：为不同来源打标签
    - `sort`：是否排序列名
    - `verify_integrity`：是否检查索引重复
- **宽表与窄表互换**：
  - **宽表（wide format）**：同一类指标分散在多列里，每一列往往代表一个类别、日期或变量名。  
    例如一行是某只股票，列是 `open`、`close`、`volume`；或者列是 `2024-01`、`2024-02`、`2024-03`。
  - **窄表/长表（long format）**：把原来分散在多列的信息压到两列或少数几列里，通常会有“变量名列 + 数值列”。  
    例如把 `2024-01`、`2024-02`、`2024-03` 三列改成两列：`month` 和 `value`，这样每个月占一行。
  - 直观地说：**宽表是“信息横着铺开”**，**窄表是“信息竖着堆叠”**。
  - 宽转窄：`melt()`，有时也可用 `stack()`
  - 窄转宽：`pivot()`、`pivot_table()`，有时也可用 `unstack()`
  - `pivot_table()` 比 `pivot()` 更稳，因为可以处理重复键并支持聚合函数
- **交易日序列补全到自然日序列**：
  - 常用思路是先构造完整自然日索引，再 `reindex()`，然后按业务需求做 `ffill()` / `bfill()`。
  - 如果是时间序列对象，也可结合 `asfreq('D')` 或 `resample('D')`。
  - `ffill()` 是 `forward fill`，即前向填充：用前面最近一个非空值往后补。
  - `bfill()` 是 `backward fill`，即后向填充：用后面最近一个非空值往前补。
  - 金融数据里一定要注意：补自然日不等于可以制造未来数据，通常只能前向填充可延续字段。
- **禁用 for 循环时的常见替代思路**：
  - 分组统计用 `groupby`
  - 排名用 `rank`
  - 滚动计算用 `rolling`
  - 累积统计用 `cumsum`、`cummax` 等
  - 窗口运算、分组变换用 `transform`
  - 表连接用 `merge`

#### 2. 排序、分组、窗口与类 SQL 思维

- **并列排序**：
  - `rank(method='min')`：并列名次取最小，如 `1,1,3`
  - `rank(method='dense')`：并列后名次连续，如 `1,1,2`
  - `rank(method='first')`：按出现顺序打破并列
  - 面试里常追问你是否知道“并列后下一名是否跳号”
- **部门中薪资高于经理的成员**：
  - 典型做法是员工表自连接，把员工和经理匹配到同一行，再筛选 `emp_salary > mgr_salary`
  - Pandas 常用 `merge`，SQL 常用自连接
- **窗口函数/窗口思想**：
  - 即便面试官只说 Pandas，很多题本质仍是 SQL 窗口思路翻译成 `groupby + transform/rank/rolling`
  - 重点是你要能把“按组处理，但不压缩原表行数”的思想讲清楚

#### 3. Python 并发与工程基础

- **多线程 vs 多进程**：
  - 进程是资源分配的最小单位，线程是任务调度的最小单位。
  - 线程共享同一进程内存，创建开销小，适合 I/O 密集任务
  - 进程彼此独立，资源隔离更强，适合 CPU 密集任务
  - Python 中还要结合 GIL 理解：纯 Python CPU 密集型任务通常多进程更有效
  
- **本地优化内存的方法**：
  - 降低数据精度：如 `float64 -> float32`、`int64 -> int32/int16`
  - 高重复字符串转 `category`
  - 分块读取大文件，如 `chunksize`
  - 及时删除中间变量，必要时 `gc.collect()`
  - 避免不必要的副本，注意链式操作和隐式复制
  - 用更合适的数据格式，如 `parquet` 替代笨重文本
- **定位首次报错版本号**：
  - 这是经典“First Bad Version”题。
  - 如果版本具有单调性，即某个版本开始后都报错，则应使用二分查找，时间复杂度 `O(log n)`。

#### 4. 机器学习与特征工程

- **回归 vs 分类**：
  - 回归预测连续值，信息更细，但对噪声更敏感
  - 分类输出离散类别，更易落地成买卖决策，但会损失部分连续信息
  - 在量化里常见做法是两者都试：回归预测收益，分类预测方向或分层标签
- **特征筛选方法**：
  - 线性方法：相关系数（看特征与目标的线性相关强弱）、t 检验（检验单个变量系数是否显著）、方差分析（比较不同组均值差异是否显著）、Lasso（用 L1 正则把部分不重要特征系数压到 0）、逐步回归（按规则逐步加入或剔除变量）、VIF（衡量一个变量与其他变量的共线性强不强）
  - 非线性方法：树模型特征重要性（看特征在树分裂中带来的增益或降损失贡献）、互信息（看特征和目标之间是否存在统计依赖关系，不限线性）、Permutation Importance（打乱某个特征后看模型性能下降多少）、SHAP（衡量每个特征对单个样本预测的边际贡献）、RFE（递归删除最不重要特征，反复训练筛出较优子集）
  - `L1` 正则（惩罚系数绝对值之和，容易把一部分系数直接压成 0，所以常用于特征筛选）；`L2` 正则（惩罚系数平方和，通常把系数压小但不压成 0，更常用于抑制过拟合和缓解共线性）。前者对应 `Lasso`，后者对应 `Ridge`。
  - 实际上还要结合业务逻辑、稳定性和共线性一起判断
- **树模型筛选特征的依据**：
  - 常见是分裂带来的损失下降、信息增益、Gini 降低、分裂次数或基于置换的重要性
  - 但树重要性会偏向高基数特征或易切分特征，不能盲信
- **样本不平衡处理方法**：
  - 重采样：过采样、欠采样、SMOTE
  - 改损失函数：类别加权、Focal Loss
  - 改评估指标：不要只看 Accuracy，应看 Precision、Recall、F1、AUC、PR-AUC
  - 调阈值：根据业务目标调节分类阈值
- **SMOTE 原理**：
  - 不是简单复制少数类样本，而是在少数类样本及其近邻之间做插值，生成新的合成样本
  - 优点是减少纯复制带来的过拟合
  - 风险是可能在噪声点附近合成出质量不高的新样本
- **XGBoost 中处理样本不平衡的参数**：
  - `XGBoost`（一种基于梯度提升树的集成学习模型，擅长处理表格数据、非线性关系和特征交互）
  - 最常问的是 `scale_pos_weight`（给正类样本损失加权，用来缓解正负样本数量不平衡）
  - 二分类里常设置为 `负样本数 / 正样本数` 的近似值作为起点，再结合验证集微调

>  - 神经网络是一类由多层神经元组成的非线性模型，通过前向传播产生预测、通过反向传播更新参数，从而自动学习输入特征到输出结果之间的复杂映射关系。核心是两个步骤：
>    - 前向传播：输入数据，算出预测值
>    - 反向传播：根据预测误差，反过来调整权重参数。训练很多轮后，模型就逐渐学到从输入到输出的映射关系。

- **LSTM / GRU 相较于 RNN 的优势**：
  - `RNN`（循环神经网络，通过把前一时刻的状态传到下一时刻，让模型具备处理序列和上下文的能力。适合处理序列数据，但普通 RNN 容易出现梯度消失或爆炸）
  - `LSTM`（长短期记忆网络，在 RNN 基础上加入更复杂的 **门控** [用若干个取值在 0~1 之间的控制变量，对信息进行选择性保留、遗忘和输出的机制。有输入门、输出门和遗忘门，所以 LSTM 本质上是在做三件事：①忘掉一部分旧信息②写入一部分新信息③输出一部分当前有用的信息] 和 **记忆单元** [是 LSTM 中专门用于保存长期历史信息的内部状态，通常记为 C_t，它在门控机制控制下对旧信息进行保留、遗忘和更新，从而提升长期依赖建模能力。]，擅长捕捉长期依赖）
  - `GRU`（**门控循环单元**，是比 LSTM 更轻量的门控循环网络[**更新门**：决定旧信息保留多少、新信息加入多少 ；**重置门**：决定在生成当前候选状态时，旧信息参考多少。]，参数更少、训练更快）
  - 都通过**门控机制**缓解梯度消失，能更好建模长期依赖
  - `GRU` 结构更简洁，参数更少，训练通常更快，`LSTM` 表达能力更强一些，但也更重

#### 5. 因子量纲、波动性与有效性评价

- **因子数据量级不统一如何解决**：
  - 标准化：Z-score
  - 排名化：Rank / 百分位
  - 去极值后再标准化：如 MAD + Z-score
  - 行业/市值中性化后再比较
  - 对偏态严重的数据可做对数变换或 Box-Cox 类变换
- **因子的波动性如何评估**：
  - 时序波动：标准差、滚动标准差、变异系数
  - 截面稳定性：分位数组成是否稳定、IC 波动是否过大
  - 可结合换手率一起看，因为高波动因子往往伴随高换手
- **因子有效性评价指标**：
  - RankIC（因子排序与未来收益排序的相关性，衡量排序预测能力，$RankIC_t = corr(rank(F_t), rank(R_{t+1}))$，此处corr为Spearman相关系数）、IC（因子值与未来收益的相关性，衡量线性预测能力，$IC_t = corr(F_t, R_{t+1})$）、IC_IR（IC 均值除以 IC 标准差，衡量预测能力的稳定性，$\mathrm{IC\_IR}=\frac{\mathrm{mean}(IC_t)}{\mathrm{std}(IC_t)}$）。IC值就是某个因子当前值和未来期收益率的相关系数。
  - 分层收益、Top-Bottom 多空收益
  - 胜率、稳定性、样本内外一致性
  - 换手率、交易成本后收益、容量约束
- **头脑风暴题 / 绿皮书题**：
  - 这类题没有唯一答案，重点不是背结论，而是展示你如何拆问题、如何设假设、如何验证。
  - 回答时建议用“先定义问题 -> 再列假设 -> 再给分析框架 -> 最后说验证方式”的结构。

### Python与研究代码习惯



### 1. 变量、对象和 `return`

- 在 Python 里，变量更像一个“名字标签”，它指向某个值或对象。
- 例如 `fee_rate = 0.001`，意思不是“创造一个叫 fee_rate 的盒子”，而是“让名字 `fee_rate` 指向数值 `0.001`”。
- 如果一个函数算出了结果，但没有 `return`，外面就拿不到这个结果。

极小例子：

```python
x = 10

def double(n):
    return n * 2

print(double(x))
```

常见误区：

- 以为函数里算过一次，函数外就自动能用到。
- 把 `print(result)` 和 `return result` 混为一谈。`print` 是显示给人看，`return` 是交给后续代码继续使用。

### 2. 列表（list）是什么？它和字典有什么区别？

- 列表是**有顺序**的数据结构，适合保存“一串同类数据”，比如价格序列、收益率序列。
- 列表最常见的特征是：
  - 用 `[]` 表示
  - 用下标取值，如 `prices[0]`
  - 可以用 `append()` 继续往后追加
- 和字典不同：列表靠“位置”取值，字典靠“名字”取值。

极小例子：

```python
prices = [100, 101, 103]
prices.append(105)
print(prices[1])
```

常见误区：

- 把下标和第几个元素混淆。Python 从 `0` 开始计数，所以第 1 个元素是 `prices[0]`。
- 在循环内部反复把列表重新写成 `[]`，会把前面辛苦存下来的结果清空。

本节怎么用：

- `calc_returns(prices)` 里用列表顺序保存每一期收益率，因为收益率天然是一段有先后顺序的数据。

### 3. 切片（slice）是什么？它和单个下标取值有什么区别？

- 切片表示：一次从列表里取出一段连续元素。
- 基本写法是 `values[a:b]`，意思是从下标 `a` 开始取，到下标 `b` 前结束。
- 你可以先把它理解成“左边包含，右边不包含”。

极小例子：

```python
values = [10, 20, 30, 40, 50]
print(values[1:4])
```

结果会是：

```python
[20, 30, 40]
```

和普通下标取值的区别：

- `values[2]` 取的是单个元素
- `values[1:4]` 取的是一整段子列表

常见误区：

- 以为切片右边也会包含进去。其实 `values[1:4]` 不会取到下标 `4`。
- 把切片和 `range()` 搞混。`range()` 生成一串整数，切片是按下标从已有列表里取一段数据。

本节怎么用：

- 后面的移动平均练习里会出现 `window_values = values[i + 1 - window:i + 1]`，它的作用就是一次取出一个窗口长度的数据片段，再对这个窗口求平均。

### 4. 字典（dict）是什么？它和列表、普通变量有什么区别？

- 字典是“键 -> 值”的结构，适合把多个结果按名字打包在一起。
- 用花括号 `{}` 表示，每一项写成 `键: 值`。
- 列表适合存一串同类数据；字典适合存“同一个对象的多个属性/结果”。

极小例子：

```python
summary = {
    "mean": 0.01,
    "max": 0.03,
    "min": -0.02,
}
print(summary["mean"])
```

常见误区：

- 以为字典和变量名是一回事。变量名是代码里的名字；字典的键是数据里的一部分。
- 忘记键不存在时会报 `KeyError`。

本节怎么用：

- `summarize_numbers(nums)` 返回字典，是因为它需要同时返回均值、最大值、最小值。用名字取值，比记 `result[0]`、`result[1]` 更不容易弄错。

### 5. `def`、参数与函数封装

- `def` 用来定义函数。函数的价值是把重复逻辑收起来，之后只要传不同参数就能反复使用。
- 参数可以理解成“把外部数据送进函数”的入口。
- 和顺序写代码相比，函数更适合量化研究里反复试参数、重复跑实验的场景。

极小例子：

```python
def add(a, b):
    return a + b

print(add(2, 3))
```

常见误区：

- 定义了函数但忘了调用。
- 函数名、参数名起得太随意，后面自己也看不懂。

### 6. `for` 和 `range()` 为什么常一起出现？

- `for` 用来重复执行一段代码。
- `range()` 用来生成一串整数，常配合下标循环使用。
- 在收益率计算里，之所以从 `1` 开始，是因为第 `0` 个价格没有“前一天价格”可比。

极小例子：

```python
for i in range(1, 4):
    print(i)
```

常见误区：

- 把 `range(1, 4)` 理解成包含 4。实际上它只会得到 `1, 2, 3`。
- 忘记缩进，导致循环体没有真正进入 `for`。

### 7. `if / else` 和 `try / except` 有什么区别？

- `if / else` 是**先判断条件，再决定走哪条路**。
- `try / except` 是**先尝试运行，真的出错了再处理**。
- 两者都能“分支”，但处理的问题不同：
  - `if / else` 更像事前检查
  - `try / except` 更像事后补救

极小例子：

```python
if b != 0:
    result = a / b
else:
    result = None
```

```python
try:
    result = a / b
except ZeroDivisionError:
    result = None
```

常见异常类型（速查）：

- `ZeroDivisionError`：除数为 0（如 `a / 0`）
- `TypeError`：类型不匹配（如把字符串和数字相加、给函数传错类型参数）
- `ValueError`：类型对但值不合法（如 `int("abc")`、日期解析失败）
- `IndexError`：下标越界（如 `prices[len(prices)]`）
- `KeyError`：字典或 `DataFrame` 列名不存在（如 `d["no_such_key"]`、`df["no_such_col"]`）
- `FileNotFoundError`：文件路径不存在（后面读取本地数据时常见）

本节怎么用：

- `safe_divide(a, b)` 里用 `try / except`，是为了在除数为 0 时不让程序直接中断，而是优雅地返回 `None`。

### 8. `Path` 和普通字符串路径有什么区别？

- 普通字符串路径只是文本，比如 `"data/prices.csv"`。
- `Path` 是专门表示路径的对象，适合做拼接、判断、读写等操作。
- 对初学者来说，可以把它理解成“更聪明的路径表示法”。

极小例子：

```python
from pathlib import Path

data_dir = Path("data")
file_path = data_dir / "prices.csv"
print(file_path)
```

常见误区：

- 把 `Path` 当成已经创建好的文件夹。`Path("data")` 只是“表示这个路径”，不等于磁盘上已经存在这个目录。
- 手写字符串拼路径时容易漏斜杠或写错平台分隔符，`Path` 能减少这类问题。

和后续内容的联系：

- 这一节先学会函数、列表、字典、异常和 `Path`，后面学 `numpy`、`pandas`、回测和项目化整理时，都会继续用到这些基础能力。

### numpy与向量化计算



### 1. 为什么这里要先学 `numpy`？

- Python 列表当然也能存数字，但它更像通用容器；`numpy.ndarray` 更像专门为数值计算准备的“数组”。
- 在量化里，经常要对整段价格、收益率、因子值做同样的运算，所以数组会比普通列表更顺手。

### 2. `import numpy as np` 是什么写法？

- 这是“导入模块并起别名”的常见写法。
- `numpy` 名字比较长，所以大家通常约定写成 `np`。
- 以后看到 `np.array()`、`np.mean()` 之类的写法，就知道是在调用 `numpy`。

极小例子：

```python
import numpy as np

arr = np.array([1, 2, 3])
print(arr)
```

### 3. 列表和 `ndarray` 有什么区别？

- 列表（list）是 Python 原生数据结构，适合通用存储。
- `ndarray` 是 `numpy` 的核心数组对象，适合批量数值运算。
- 对小白来说，可以先这样记：
  - 列表更像“普通收纳盒”
  - `ndarray` 更像“专门给数学计算准备的工具箱”

- 名字怎么读：它叫 **`ndarray`**（不是 `nparray`）。**`nd`** 表示 **n-dimensional**（n 维），即可以是一维、二维、三维等任意维度的数组；**`array`** 就是“数组”。`np.array(...)` 是**创建**数组的函数，创建出来的对象类型是 `ndarray`。

极小例子：

```python
py_list = [1, 2, 3]
np_arr = np.array([1, 2, 3])
```

常见误区：

- 以为列表和数组完全一样。它们都能存一串值，但数组支持更自然的整体运算。
- 以为只要能算就没区别。对于后面的大量数值处理，区别会越来越明显。

### 4. `np.array(...)` 和 `dtype=float` 在干什么？

- `np.array(...)` 把列表转成数组。
- `dtype=float` 表示“用浮点数来存这些值”，这对收益率、均值、波动率这类小数计算很常见。
- 如果把价格写成整数，有些计算场景也能正常工作，但提前统一成浮点数，通常更稳妥。

极小例子：

```python
prices = np.array([100, 101, 103], dtype=float)
```

相关概念：

- 标量（scalar）：单个数字，如 `100`
- 向量（vector）：一串按顺序排好的数字
- 一维数组：在这节里，你可以先把它理解成“用 `numpy` 存的一维向量”

### 5. 切片是什么？为什么收益率计算里特别重要？

- 切片就是“一次拿出数组的一部分”。
- `arr[1:]` 表示从第 2 个元素拿到最后。
- `arr[:-1]` 表示从开头拿到倒数第 2 个元素。由于 Python（以及 NumPy）里，切片写法是 [start:stop]，并且 stop 这个位置上的索引是不包含的（左闭右开），因此实际上终点是倒数第二个元素。
- 在收益率计算里，这两个切片可以把“今天价格”和“昨天价格”整段对齐。

极小例子：

```python
arr = np.array([10, 20, 30, 40])
print(arr[1:])
print(arr[:-1])
```

常见误区：

- 忘记切片是“前闭后开”风格的思路。
- 不理解为什么两个切片长度一样。其实正是因为一样，才可以逐元素计算。

### 6. 什么是向量化？它和 `for` 循环有什么区别？

- 向量化就是“把同一种运算一次作用到整段数组上”。
- `for` 循环是一个一个元素地处理；向量化是整段一起处理。
- 对初学者来说，不必一开始就追求性能，只要先形成直觉：如果一整列/一整段数据都要做同样操作，优先想一想能不能直接整体算。

极小例子：

```python
arr = np.array([1, 2, 3])
print(arr + 10)
```

和 `for` 的对比：

```python
result = []
for x in [1, 2, 3]:
    result.append(x + 10)
```

本节怎么用：

- `prices[1:] / prices[:-1] - 1` 就是最典型的向量化写法，一次直接得到整段收益率。
- 简单理解：`prices[1:]` 是「今天」那一整段，`prices[:-1]` 是「昨天」那一整段；两者长度相同、逐元素相除再减 1，就是「今/昨 − 1」，即相邻两期的简单收益率；价格若有 n 个，收益率序列长度是 n−1。

### 7. 什么是布尔索引？

- 布尔索引就是“先得到一串 True/False，再只保留满足条件的位置”。
- 这和后面 `pandas` 里的布尔筛选是相通的。

极小例子：

```python
returns = np.array([0.01, -0.02, 0.03])
print(returns[returns > 0])
```

常见误区：

- 以为 `returns > 0` 得到的是一个单独的真假值。实际上它会得到“一整段真假数组”。

### 8. `mean()`、`std()`、`max()`、`min()` 这些方法代表什么？

- `mean()`：均值，表示平均水平
- `std()`：标准差，常用来描述波动大小
- `max()`：最大值
- `min()`：最小值
- 这些都是“聚合方法”，意思是把一整段数据压缩成一个统计结果。

极小例子：

```python
arr = np.array([1, 2, 3, 4])
print(arr.mean())
print(arr.std())
```

和后续内容的联系：

- 这一节学会数组、切片、向量化和布尔索引，下一节进入 `pandas` 时，你会发现它很多操作都和这里的思路非常相似，只是对象从数组变成了带索引的表格数据。

- **定义一个价格数组，计算每日收益率 / 计算这组收益率的均值和标准差 / 筛选出所有正收益 / 写一个函数，把输入数组标准化 / 用随机数生成 20 天收益率，并计算净值曲线**

### pandas与时间序列处理



### 1. 为什么学完 `numpy` 之后要学 `pandas`？

- `numpy` 更擅长处理“一串数字”或“数值矩阵”。
- `pandas` 更擅长处理“带名字、带日期、带多列含义的表格数据”。
- 量化研究里的真实数据通常不是只有一列数字，而是有 `date`、`close`、`volume` 这类字段，所以 `pandas` 会非常常用。

### 2. `Series` 和 `DataFrame` 分别是什么？

- `Series` 可以先理解成“带索引的一列数据”。
- `DataFrame` 可以理解成“由多列 `Series` 组成的一张表”。
- 如果你学过 Excel：
  - `Series` 有点像单独一列
  - `DataFrame` 有点像整张工作表

极小例子：

```python
import pandas as pd

s = pd.Series([100, 102, 101])
df = pd.DataFrame({"close": [100, 102, 101], "volume": [1000, 1200, 900]})
```

常见误区：

- 看到都是中括号就以为取出的对象都一样。实际上单列通常得到 `Series`，多列通常得到 `DataFrame`。

### 3. `pd.DataFrame(...)` 在做什么？

- 它是在把一组列数据组织成表格。
- 每一列都有列名，每一行代表一个观测。
- 在量化里，一行通常代表某个交易日或某个标的在某个时点的数据。

极小例子：

```python
df = pd.DataFrame({
    "date": ["2025-01-02", "2025-01-03"],
    "close": [100, 102],
})
```

### 4. `df["col"]`、`df[[...]]` 和新增列分别是什么意思？

- `df["close"]`：取单列，通常得到 `Series`
- `df[["close", "volume"]]`：取多列，得到新的 `DataFrame`
- `df["return"] = ...`：给表格新增一列

极小例子：

```python
print(df["close"])
print(df[["close", "volume"]])
df["double_close"] = df["close"] * 2
```

常见误区：

- 忘了双中括号，结果以为自己取到的是表，实际上拿到的是单列。
- 新增列时左右两边长度不匹配，容易报错或结果不符合预期。

### 5. 什么是布尔筛选？它和 `numpy` 的布尔索引有什么关系？

- 布尔筛选的核心思想和 `numpy` 是一样的：先得到一列 True/False，再只保留为 True 的行。
- 只不过 `pandas` 这里筛的是“行”。

极小例子：

```python
high_volume_df = df[df["volume"] > 1000]
```

相关概念：

- 条件表达式：`df["volume"] > 1000`
- 布尔结果：一列 True/False
- 筛选结果：只保留满足条件的那些行

### 6. 什么是索引？为什么日期索引很重要？

- 索引可以理解成“每一行的标签”。
- 默认索引通常是 `0, 1, 2...`。
- 当你把 `date` 设成索引后，每一行就不再只是“第几行”，而是“某一天的数据”。
- 这对量化很重要，因为很多分析本来就是围绕时间展开的。

极小例子：

```python
df["date"] = pd.to_datetime(df["date"])
df = df.set_index("date")
```

和普通下标的区别：

- 普通下标更像“位置”
- 日期索引更像“有业务含义的标签”

### 7. `loc[]`、`shift()`、`rolling()` 分别解决什么问题？

- `loc[]`：按标签取值或切片。日期成了索引后，就可以按日期区间选数据。
- `shift(1)`：把一列数据整体错后一行，常用来取“前一天”的值。
- `rolling(3)`：创建滚动窗口，常用来算 3 日均值、3 日波动率等。

极小例子：

```python
df["prev_close"] = df["close"].shift(1)
df["ma_3"] = df["close"].rolling(3).mean()
print(df.loc["2025-01-03":"2025-01-07"])
```

常见误区：

- 忘记 `shift(1)` 后前面会出现缺失值。
- 不理解 `rolling(3)` 不是“随便取 3 个值”，而是“当前行向前看的 3 个观测窗口”。

### 8. 重新赋值为什么这么常见？

- `pandas` 里很多操作不会“默默原地改好一切”，而是返回处理后的结果。
- 所以你会经常看到：
  - `df = df.sort_values(...)`
  - `df = df.set_index(...)`
  - `df["new_col"] = ...`
- 这是一种很重要的数据处理习惯：每做一步，就明确告诉自己“现在手里的表变成什么样了”。

### 9. `pandas`、`numpy` 和 Python 列表之间是什么关系？

- Python 列表：最基础、最通用的顺序容器
- `numpy.ndarray`：更适合数值批量计算
- `pandas.Series/DataFrame`：建立在数值与索引之上的表格/时间序列结构

你可以先粗略理解成：

- 列表解决“先把数据装起来”
- `numpy` 解决“高效地算”
- `pandas` 解决“带标签、带时间、带多列地算”

和后续内容的联系：

- 这一节把日期索引、收益率、滚动均值、信号生成讲明白后，后面数据清洗、回测、因子研究都会直接复用这些思想。

### 金融数据获取与文件管理



### 1. 为什么这一节开始要先谈“数据从哪里来”？

- 前三节更多是在练 Python、`numpy`、`pandas` 的基础语法。
- 从这一节开始，你会慢慢进入真实研究环境：数据不再总是手写在代码里，而是来自文件、接口或数据库。
- 所以这节的关键不是背接口，而是先建立一个概念：**数据先被找到、再被读进来、再被整理成表格**。

### 2. 文件、文件夹和路径分别是什么？

- 文件（file）可以理解成一份具体的数据或文档，比如 `etf_prices.csv`。
- 文件夹（folder / directory）可以理解成装文件的容器，比如 `data/raw/`。
- 路径（path）就是“怎么找到某个文件或文件夹”的地址。

极小例子：

```python
from pathlib import Path

file_path = Path("data") / "raw" / "etf_prices.csv"
print(file_path)
```

相关概念：

- 相对路径：相对于当前工作目录，比如 `data/raw/etf_prices.csv`
- 绝对路径：从磁盘根位置写到完整地址，比如 `D:/shixi/python量化投资/data/raw/etf_prices.csv`

常见误区：

- 以为 notebook 放在哪，当前工作目录就一定在哪。实际上运行目录和文件所在目录不一定相同。
- 把路径当成文件本身。路径只是“地址”，不等于文件一定存在。

### 3. 为什么这里要用 `Path`，而不是一直手写字符串？

- 字符串路径当然能用，但写长了容易漏斜杠、拼错目录。
- `Path` 是专门表示路径的对象，更适合做拼接、判断、展示。
- 对初学者来说，可以把它理解成“比普通字符串更聪明的路径”。

极小例子：

```python
from pathlib import Path

data_dir = Path("data")
raw_dir = data_dir / "raw"
```

和普通字符串的区别：

- 字符串更像纯文本
- `Path` 更像带功能的路径对象

### 4. 为什么这一节还在反复写“分步赋值”？

- 因为真实项目里路径通常比较长。
- 如果你把所有内容一股脑写进一行，后面很难检查哪里错了。
- 先写 `project_root`，再写 `data_dir`、`raw_dir`、`processed_dir`，其实是在培养项目代码的组织习惯。

极小例子：

```python
project_root = Path.cwd().parent
data_dir = project_root / "data"
raw_dir = data_dir / "raw"
```

本节怎么用：

- 这一节里你会看到路径被拆成多个变量，这不是啰嗦，而是在练习“把复杂信息拆开管理”。

### 5. `pd.read_csv(...)` 这样的写法，本质上在做什么？

- 这是在调用函数，并把文件或类文件对象传给它。
- 你可以先把它理解成：“把某种格式的数据读进来，并转成 `DataFrame`”。
- CSV 是最常见的表格文本格式之一，很适合作为入门数据格式。

极小例子：

```python
import pandas as pd

df = pd.read_csv("data/raw/etf_prices.csv")
```

相关概念：

- 函数名：`read_csv`
- 参数：括号里的文件路径或对象
- 返回值：通常是一个 `DataFrame`

### 6. CSV、JSON、字典、`DataFrame` 之间是什么关系？

这是初学者特别容易混淆的一块，可以先这样理解：

- CSV：一种**表格文本格式**，适合按行按列存数据
- JSON：一种**层级结构文本格式**，常见于接口返回
- 字典（dict）：JSON 读进 Python 后，通常会先变成字典/列表组合
- `DataFrame`：适合继续分析和计算的表格对象

你可以把这一过程记成：

`文本文件 / 接口返回 -> Python 数据结构 -> DataFrame`

极小例子：

```python
import json
import pandas as pd

json_text = '{"data": [{"close": 4.12}, {"close": 4.16}]}'
obj = json.loads(json_text)
df = pd.DataFrame(obj["data"])
```

常见误区：

- 以为 JSON 一读进来就是 `DataFrame`。其实通常会先变成字典或列表。
- 以为 CSV 和 JSON 谁更高级。它们只是适合不同场景的存储格式。

### 7. 什么是“字符串”和“多行字符串”？为什么这里会用到？

- 字符串是文本数据，比如文件名、路径、接口返回内容。
- 多行字符串通常用三引号表示，适合在 notebook 里直接写一小段示例数据。
- 这样你不用真的创建文件，也能先练“读取数据”的语法。

极小例子：

```python
csv_text = """date,close
2025-01-02,4.12
2025-01-03,4.16
"""
```

### 数据清洗与对齐



### 1. 什么叫“数据清洗”？为什么量化里特别重要？

- 数据清洗不是“把表格弄漂亮”，而是检查数据能不能安全地进入后续计算。
- 量化里很怕“数据看起来有，实际上不能直接用”的情况，比如缺值、重复、日期乱序、未来信息提前泄露。
- 所以这一节是在练一种很重要的思维：**先怀疑数据，再相信结果**。

### 2. 缺失值、重复值、异常值分别是什么？

- 缺失值：某个位置没有数据，比如价格空了
- 重复值：同一条记录出现了不该重复的多次
- 异常值：数值明显不合理，可能是录入错误、复权问题、数据源问题

你可以先把它们理解成三类常见“脏数据”：

- 没有
- 多了
- 不对劲

常见误区：

- 以为只要表能读出来就算干净。
- 看到缺失值就立刻填 0，而不先问“这个缺失到底代表什么”。

### 3. 为什么这里还会再次用字典创建 `DataFrame`？

- 因为在教学和测试里，自己构造一个小型脏数据表最直观。
- 你可以清楚地控制哪里缺、哪里重、哪里异常，而不必先找一份真实脏文件。

极小例子：

```python
price_df = pd.DataFrame({
    "date": ["2025-01-02", "2025-01-03"],
    "close": [4.12, None],
})
```

### 4. 缺失值是怎么表示的？`isna()` 在干什么？

- 在 `pandas` 里，缺失值常会显示成 `NaN` 或 `None`。
- `isna()` 的作用不是填值，而是先告诉你“哪些位置缺了”。
- 这一步很像体检前先查问题，而不是还没看报告就急着吃药。

极小例子：

```python
print(price_df.isna())
print(price_df.isna().sum())
```

相关概念：

- `isna()`：判断是否缺失
- `sum()`：把 True/False 当作 1/0 统计缺失个数

常见误区：

- 以为 `isna()` 会自动修复缺失值。它只是检查，不是修复。

### 5. 什么是 `copy()`？为什么这里要复制一份再改？

- `copy()` 可以理解成“先复制一份，再在副本上继续操作”。
- 这样你可以保留原始表，同时明确哪一份是“处理中间结果”。
- 对初学者来说，这个习惯非常重要，因为数据清洗通常不是一步完成，而是很多步逐渐变干净。

极小例子：

```python
dedup_df = price_df.drop_duplicates()
filled_df = dedup_df.copy()
```

常见误区：

- 在同一个对象上反复改，却忘了自己前面做过什么，最后很难追踪问题。

### 6. 为什么要排序？为什么经常按 `symbol + date` 一起排？

- 时间序列分析默认有一个前提：时间顺序是对的。
- 如果日期顺序错了，收益率、滚动均值、滞后值都可能算错。
- 多标的数据还要考虑不同标的不能串行，所以常用 `["symbol", "date"]` 一起排序。

极小例子：

```python
dedup_df = dedup_df.sort_values(["symbol", "date"])
```

相关概念：

- 单列排序：只按一个字段排
- 多列排序：先按第一个字段分组，再在组内按第二个字段排

### 7. 缺失值处理为什么不能“无脑填充”？

- 因为不同字段的缺失含义不同。
- 价格缺失、成交量缺失、因子值缺失，背后的业务原因可能完全不一样。
- 所以真正重要的不是会不会 `fillna()`，而是知道**什么时候该填、什么时候不该填、填什么才合理**。

极小例子：

```python
filled_df["close"] = filled_df["close"].ffill()
filled_df["volume"] = filled_df["volume"].fillna(0)
```

常见误区：

- 把所有缺失都统一填成 0。
- 看到 `ffill()` 好用，就对所有列都前向填充。

### 8. 什么是异常值？为什么要先“检查”再决定怎么处理？

- 异常值不一定是错误，但一定值得怀疑。
- 比如某天收益率突然跳到 20%，可能是真的暴涨，也可能是复权、停牌恢复、脏数据带来的假信号。
- 入门阶段可以先学会“把异常找出来”，不要急着一上来就删除。

极小例子：

```python
filled_df["return"] = filled_df["close"] / filled_df["close"].shift(1) - 1
print(filled_df[filled_df["return"].abs() > 0.08])
```

### 9. 什么叫“对齐”？`merge()` 到底在干什么？

- 对齐的意思是：把本来分散在不同表里的信息，按照共同键拼到一起。
- 在量化里，最常见的共同键是 `date` 和 `symbol`。
- `merge()` 本质上就是告诉 Python：请按这些键，把两张表对上号。

极小例子：

```python
merged_df = filled_df.merge(
    factor_df,
    on=["date", "symbol"],
    how="left"
)
```

相关概念：

- `on=[...]`：按哪些列对齐
- `how="left"`：保留左表所有行
- 对齐后因子缺失时，会出现 `NaN`

常见误区：

- 只看代码跑没跑通，不检查合并后行数有没有变怪。
- 忘记先把日期类型统一好，就直接合并。

### 10. 什么是未来函数 / 数据泄露？

- 这是量化里非常重要的概念：你在今天做决策时，不能偷偷用了未来才知道的数据。
- 如果不小心把未来信息混进来，结果会看起来很好，但实际上完全不可用。
- 所以这一节讲“清洗与对齐”，其实不只是技术问题，也是研究严谨性问题。

初学者可以先记住一句话：

- **回测或研究里，今天只能用今天之前已经知道的信息。**

### 11. 这一节和后面章节怎么衔接？

- 这一节解决的是“数据能不能放心拿去算”。
- 下一步你会开始更频繁地计算收益、波动率、信号、净值。
- 如果这一步没做好，后面再漂亮的指标和图表都可能是错的。

- **构造一个带缺失值和重复值的价格表 / 统计每列缺失值数量 / 删除重复值 / 把 `date` 转成日期并排序 / 用前向填充处理价格缺失值 / 构造一个因子表，并按 `date + symbol` 合并 / 用一句话解释什么是未来函数**

> 🏷️ 标签：量化编程，数据清洗与对齐

### 收益率波动率与基础指标计算



### 1. 这一节到底在学什么？

- 前面几节更多是在处理数据、准备数据。
- 这一节开始，你会接触“研究结果怎么量化表达”。
- 也就是说，我们不再只问“有没有算出来”，而是开始问：
  - 赚了多少
  - 波动大不大
  - 回撤深不深
  - 风险和收益是否匹配

### 2. `Series` 在这一节里为什么特别适合表示收益率？

- 收益率通常是一串按时间顺序排列的数据。
- `Series` 很适合表达“单列、有顺序、可以继续算统计量”的对象。
- 如果后面给它加上日期索引，它还能自然地和时间对应起来。

极小例子：

```python
import pandas as pd

returns = pd.Series([0.01, -0.005, 0.012])
print(returns)
```

### 3. 收益率、净值、累计收益分别是什么？

这三个概念很容易混：

- 收益率：某一段时间赚了多少，比如某一天涨了 1%
- 净值：把收益不断累计后的资金曲线，常把初始值设为 1
- 累计收益：期末净值减去 1，表示从开始到结束总共赚了多少

你可以先这样记：

- 收益率是“每天发生了什么”
- 净值是“账户走成什么样了”
- 累计收益是“最后总共赚了多少”

极小例子：

```python
returns = pd.Series([0.01, -0.005, 0.012])
nav = (1 + returns).cumprod()
cum_return = nav.iloc[-1] - 1
```

常见误区：

- 把“平均收益率”当成“累计收益”。它们不是一回事。
- 看到净值变成 1.08，不知道它其实对应累计收益 8%。

### 4. 什么是方法调用链？为什么这里一直看到 `(1 + returns).cumprod()`？

- 方法调用链表示：前一步的结果，立刻继续做下一步操作。
- `(1 + returns)` 先把每期收益率变成“每期增长倍数”。
- `.cumprod()` 再把这些增长倍数一路连乘，得到净值曲线。

极小例子：

```python
nav = (1 + returns).cumprod()
```

本节怎么用：

- 这是从“收益率序列”走到“净值曲线”的核心一步，后面回撤和很多绩效指标都建立在它上面。

### 5. `iloc[-1]` 为什么总是出现？

- `iloc` 是按位置取值。
- `-1` 表示最后一个位置。
- 所以 `nav.iloc[-1]` 常被用来拿“最后一天的净值”，也就是期末结果。

极小例子：

```python
print(nav.iloc[-1])
```

相关概念：

- `iloc[0]`：第一个位置
- `iloc[-1]`：最后一个位置
- 在时间序列里，最后一个位置通常就是“期末”

### 6. 波动率到底在表达什么？

- 波动率不是“涨得多不多”，而是“收益上下晃动得厉不厉害”。
- 两个策略即使累计收益相近，波动率也可能差很多。
- 初学者可以先把 `std()` 理解成“波动大小的一个度量”。

极小例子：

```python
volatility = returns.std()
```

常见误区：

- 以为收益高就一定好。量化里还要看它是不是波动特别大、坐过山车一样赚来的。

### 7. 年化收益和年化波动率是什么？为什么要年化？

- 年化的目的，是把不同长度的数据放到更容易比较的尺度上。
- 日收益率、月收益率、年收益率原本不在同一个单位上，直接比不方便。
- 所以常会把它们换算到“一年大概是什么水平”。

极小例子：

```python
annual_factor = 252
annual_return = (1 + mean_return) ** annual_factor - 1
annual_volatility = volatility * np.sqrt(annual_factor)
```

相关概念：

- 252：日频里常用的一年交易日近似值
- 年化不是“预测未来一定这样”，而是“把当前统计结果换成年度尺度”

### 8. 回撤和最大回撤是什么？

- 回撤表示：当前净值比历史最高点低了多少。
- 最大回撤表示：整段期间里最深的一次下跌幅度。
- 如果说净值曲线告诉你“总体走得怎么样”，那回撤更像是在告诉你“中间最难受的时候有多惨”。

极小例子：

```python
rolling_max = nav.cummax()
drawdown = nav / rolling_max - 1
max_drawdown = drawdown.min()
```

常见误区：

- 只看最终赚没赚钱，不看中间经历过多大回撤。
- 以为最大回撤是正数。这里通常是负数，因为它表示“从高点往下跌了多少”。

### 9. 夏普比率在直觉上怎么理解？

- 夏普比率可以先粗略理解成：“每承担一单位波动，换来了多少收益。”
- 它不是在问“赚没赚钱”，而是在问“赚得值不值、稳不稳”。
- 入门阶段先理解简化版写法就够了。

极小例子：

```python
sharpe = annual_return / annual_volatility
```

常见误区：

- 把夏普比率当成越高越绝对好。它只是一个角度，不是唯一标准。

### 10. 为什么这一节总是把指标拆成很多中间变量？

- 因为指标计算如果全部写在一行，初学者很难看懂，也不方便查错。
- 把 `nav`、`cum_return`、`volatility`、`drawdown` 分开写，本质上是在训练你把复杂计算拆成小步骤。
- 这和后面写回测、写项目代码的思路完全一致。

- 下一节会继续解决“结果怎么用图表表达”。

### 可视化与策略结果表达



### 1. 为什么量化研究一定要学可视化？

- 因为很多结果用一串数字很难一下看懂。
- 例如净值、回撤、收益分布、策略和基准对比，这些都更适合用图来表达。
- 图表不是“装饰品”，而是在帮你更快发现趋势、风险和异常。

### 2. 这一节里会遇到哪些图？它们分别在看什么？

- 折线图：适合看随时间变化的趋势，比如净值曲线
- 回撤图：适合看策略在哪些阶段跌得深
- 直方图：适合看收益率分布是否集中、是否有极端值
- 柱状图：适合横向比较多个指标

你可以先这样记：

- 看时间变化，用折线图
- 看分布形状，用直方图
- 看横向对比，用柱状图

### 3. 为什么这一节会同时导入 `pandas`、`numpy`、`matplotlib`？

- `pandas` 负责表格数据
- `numpy` 负责一些数值辅助计算
- `matplotlib` 负责真正把图画出来
- 这也说明真实研究里，一个 notebook 往往不是只用一个库，而是多个工具配合完成任务。

极小例子：

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
```

### 4. 为什么画图前总要先准备好多列？

- 因为图不是凭空画出来的，图里的每条线、每组柱子，都来自某些列。
- 所以画图前通常要先把 `strategy_nav`、`benchmark_nav`、`drawdown` 这类列算出来。
- 这一步其实是在把“研究结果”整理成能直接展示的结构。

极小例子：

```python
strategy_df["strategy_nav"] = (1 + strategy_df["strategy_return"]).cumprod()
strategy_df["strategy_drawdown"] = strategy_df["strategy_nav"] / strategy_df["strategy_nav"].cummax() - 1
```

### 5. 坐标轴、标题、图例分别在干什么？

- 标题：告诉读者这张图在看什么
- 横轴（x 轴）：通常表示时间或类别
- 纵轴（y 轴）：通常表示净值、回撤、频数等数值
- 图例（legend）：说明不同颜色/线条分别代表谁

常见误区：

- 图能画出来就算完，其实如果没有标题、坐标轴和图例，别人很难快速读懂。

### 6. `figsize`、`label`、`color` 这些参数为什么重要？

- `figsize`：控制图的大小，太小会挤在一起看不清
- `label`：给曲线或柱子起名字，方便图例显示
- `color`：让不同对象更容易区分
- 这些参数不改变研究结论，但会显著影响表达效果。

极小例子：

```python
plt.figure(figsize=(8, 4))
plt.plot(x, y, label="Strategy", color="blue")
```

### 7. 为什么画图要讲“顺序”？

- 因为 `matplotlib` 通常是一步一步把图搭出来的。
- 一般顺序是：
  - 先创建画布
  - 再把数据画上去
  - 再补标题、坐标轴、图例
  - 最后调整布局并显示
- 形成稳定顺序后，你以后画更复杂的图也不容易乱。

极小例子：

```python
plt.figure(figsize=(8, 4))
plt.plot(x, y)
plt.title("Example")
plt.tight_layout()
plt.show()
```

### 8. 为什么净值曲线和回撤曲线要分开看？

- 净值曲线告诉你“总体看起来涨得怎么样”。
- 回撤曲线告诉你“中间最难受的时候有多难受”。
- 有些策略净值曲线看起来不错，但回撤可能很深，所以两张图必须配合看。

### 9. 收益率分布图在看什么？

- 它不是看时间顺序，而是在看“收益值大多落在哪些区间”。
- 如果分布特别偏、尾部特别长，通常意味着极端波动或不稳定性值得关注。
- 所以它和净值图不是重复信息，而是在看另一个角度。

### 10. 为什么量化输出不能只有图，还要有文字结论？

- 因为图虽然直观，但结论需要明确表达。
- 读图的人不一定会自动替你总结“策略好在哪里、风险在哪里、和基准差在哪”。
- 所以好的结果表达通常是：图表 + 指标 + 文字结论。

初学者可以先记住一个简单模板：

1. 结果是什么
2. 风险在哪里
3. 和基准比怎么样
4. 下一步还要验证什么

- 这一节解决的是“结果怎么展示”。
- 下一节会进入基础回测，真正把信号、持仓、收益、成本串成完整流程。
- 到那时你会发现，这一节画图用到的净值、回撤、指标，都会直接成为回测结果的一部分。

### 项目化实战与代码工程化



### 1. 为什么最后一节要讲“项目化”和“工程化”？

- 因为前面你已经学了很多单点技能：数据读取、清洗、指标、回测、因子、机器学习。
- 但真实工作里，差距往往不只在“会不会某个函数”，而在“能不能把这些东西组织成一个清楚、可复用、别人也能接手的项目”。
- 所以这一节是在把前面所有内容收束成一个更完整的研究工程视角。

### 2. 什么叫“项目结构”？

- 项目结构可以理解成：不同类型的内容放在不同位置，各自承担不同职责。
- 例如：
  - `data/` 放数据
  - `notebooks/` 放探索过程
  - `src/` 放可复用代码
  - `outputs/` 放结果导出
- 这样做的目的不是形式好看，而是让项目更容易查找、修改和复用。

### 3. 什么叫“模块化”？

- 模块化的核心思想是：把大问题拆成小模块，每个模块只负责一件相对清楚的事。
- 比如：
  - 一个函数负责准备数据
  - 一个函数负责生成信号
  - 一个函数负责回测
  - 一个函数负责评估
- 这和前面学过的方法拆分类似，只是现在把视角提升到了整个项目层面。

### 4. 为什么“能跑”不等于“好维护”？

- 一段代码今天能跑，不代表一个月后你还能快速看懂它。
- 如果所有逻辑都堆在一个 notebook 里：
  - 改参数容易漏
  - 找 bug 很痛苦
  - 很难复用
  - 别人接手成本也很高
- 工程化的目标，就是让代码不只是今天能跑，还要未来能改、能复现、能协作。

### 5. `CONFIG` 为什么重要？

- `CONFIG` 字典的价值，不只是“把参数放一起”。
- 它更重要的作用是：把原本散落在各处的关键设置集中管理。
- 这样一来，当你调整均线窗口、费率、年化因子时，不需要满文件找“魔法数字”。

极小例子：

```python
CONFIG = {
    "ma_window": 3,
    "fee_rate": 0.001,
    "annual_factor": 252,
}
```

常见误区：

- 以为配置只是“高级写法”。其实对初学者来说，它反而能显著减少混乱。

### 6. 为什么路径和目录在项目里更重要了？

- 前面你已经学过 `Path` 和数据目录。
- 到项目阶段，这件事变得更重要，因为数据、代码、结果都开始分散到不同目录。
- 如果路径管理混乱，项目很快就会失控。

### 7. 多步骤流程串联是什么意思？

- 项目代码通常不是一段独立代码，而是一个个步骤首尾相接：
  - 读取数据
  - 清洗数据
  - 生成特征
  - 生成信号
  - 回测
  - 评估
- 你可以把它理解成“研究流水线”。
- 这一节做的事，就是把这条流水线写得更清楚，而不是把所有步骤混在一个大代码块里。

### 8. 为什么要把函数拆开？

- 因为每个函数都在承担一个明确职责。
- 例如：
  - `prepare_data()` 只管准备数据
  - `add_features()` 只管生成特征
  - `generate_signal()` 只管生成信号
  - `run_backtest()` 只管回测
- 这样以后你想换掉某一步逻辑，不必把整段代码全部重写。

极小例子：

```python
def generate_signal(df):
    df = df.copy()
    df["signal"] = (df["close"] > df["ma"]).astype(int)
    return df
```

### 9. 为什么要区分 `data`、`src`、`outputs`？

- 因为它们分别代表三类完全不同的东西：
  - `data`：输入
  - `src`：处理逻辑
  - `outputs`：结果输出
- 一旦这三类东西混在一起，项目会变得越来越难维护。
- 所以目录结构本质上也是在练“职责边界”。

### 10. notebook 和项目代码分别扮演什么角色？

- notebook 更适合探索、试想法、做临时实验
- 项目代码更适合沉淀稳定逻辑、重复运行和正式复用
- 你可以先把 notebook 看成“研究草稿本”，把 `src` 看成“整理好的正式版本”

常见误区：

- 以为 notebook 不需要整理。其实如果 notebook 永远不沉淀成模块，项目很容易越做越乱。

### 11. 这一节为什么是整套课的收尾？

- 因为它是在告诉你：前面学到的每一块能力，最后都不是孤立存在的。
- 数据、指标、回测、评估、图表、组合、模型，这些最终都要被组织成一个完整项目。
- 所以这节不是“额外附加”，而是把前面内容真正落到实战方式里的最后一步。

### 12. 你应该带走的核心思路是什么？

- 不要只追求“代码能跑”。
- 要开始追求：
  - 结构清楚
  - 参数集中
  - 逻辑可复用
  - 结果可复现
  - 别人能看懂
- 这就是从“会写 notebook”走向“会做量化项目”的关键一步。

- **设计一个你自己的量化项目目录结构 / 写一个 `CONFIG` 字典管理参数 / 把“准备数据 -> 生成信号 -> 回测 -> 评估”拆成 4 个函数 / 生成一份指标表 / 用 3 句话写一段项目说明**
