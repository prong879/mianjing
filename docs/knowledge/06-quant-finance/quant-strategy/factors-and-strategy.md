### 三、 因子研究与策略评价

### 1. 因子评价指标：IC 与 IC_IR

- **Rank IC（秩相关系数）**：
  - *定义*：第 $t$ 期的因子暴露度排名，与第 $t+1$ 期的收益率排名之间的 Spearman 相关系数。
  - *标准*：通常单因子 IC 均值 > 0.03 (3%) 就算是有预测能力了。
- **IC_IR（信息比率）**：
  - *公式*：`IC均值 / IC的标准差`。
  - *意义*：衡量因子预测能力的**稳定性**。如果一个因子时而极准，时而极错（标准差大），IR就会低；稳定赚钱的因子IR高。通常要求 IR > 0.5。

### 2. 策略评价指标（净值曲线分析）

假设你有一个每日收益率序列 `returns` (Pandas Series)。

- **年化收益率 (Annualized Return)**：
  - 日频数据年化：`returns.mean() * 252` （252是每年交易日）
- **年化波动率 (Annualized Volatility)**：
  - 日频波动率年化：`returns.std() * np.sqrt(252)`
- **夏普比率 (Sharpe Ratio)**：
  - *公式*：`(年化收益率 - 无风险利率) / 年化波动率`
  - *代码*：`(returns.mean() * 252 - 0.02) / (returns.std() * np.sqrt(252))`
  - *意义*：每承担1单位风险，能获得多少超额回报。CTA策略夏普 > 1.0 算优秀。
- **最大回撤 (Maximum Drawdown)**：
  - *定义*：在选定周期内，从历史最高点跌到最低点的最大跌幅。衡量策略的极端风险。
  - *数学公式*：若第 `t` 期收益率为 `r_t`，则累计净值为
    $$
    NAV_t = \prod_{k=1}^{t}(1+r_k)
    $$
    历史最高净值为
    $$
    Peak_t = \max_{1 \le s \le t} NAV_s
    $$
    则第 `t` 期回撤为
    $$
    DD_t = \frac{NAV_t - Peak_t}{Peak_t}
    $$
    最大回撤为
    $$
    MDD = \min_{1 \le t \le T} DD_t
    $$
    若写成正数口径，也常写为
    $$
    MDD = \max_{1 \le t \le T}\left(1-\frac{NAV_t}{Peak_t}\right)
    $$
  - *代码实现（重点，常考手写）*：
    ```python
    # 1. 计算累计净值
    cum_nav = (1 + returns).cumprod()
    # 2. 计算历史最高净值
    running_max = cum_nav.cummax()
    # 3. 计算回撤比例
    drawdown = (cum_nav - running_max) / running_max
    # 4. 取最小值（负数）
    max_drawdown = drawdown.min()
    ```

### 2. 因子挖掘与验证

- **常见因子挖掘方法**：
  - 经济逻辑驱动：从估值、基本面、行为金融、期限结构、波动率等理论出发构建因子。
  - 文献复现驱动：复现经典论文因子，再做本土市场和样本外检验。
  - 数据驱动：从大量候选特征中做筛选，如相关性分析、逐步筛选、Lasso、树模型重要性、AutoML。
  - 组合构造：已有因子做正交化、加权融合、分层组合或状态切换。
- **因子有效性验证**：
  - 截面预测能力：IC、RankIC、IC_IR。
  - 可交易性：分层收益、Top-Bottom 多空收益、换手率、冲击成本、容量约束。
  - 稳定性：滚动窗口、牛熊分段、行业分段、样本内/样本外一致性。
  - 显著性：t 检验、Bootstrap（对样本反复有放回重抽样，近似估计统计量分布和显著性）、置换检验等。
- **机器学习因子的验证方式**：
  - 严格按时间**切分**训练集、验证集、测试集，不能随机打乱。
  - 采用滚动训练/滚动预测，模拟真实投研流程。
  - 除预测误差外，更重要的是看分组收益、IC、RankIC、成本后收益和稳定性。
  - 对模型解释可补充特征重要性、SHAP、Permutation Importance。
- **为什么经常用 RankIC**：
  - 股票和期货截面里极端值多、噪声大，普通 Pearson IC 容易被异常点扭曲。
  - RankIC 只关心**排序关系**，更适合“选股/选品种”这类截面决策。
  - 许多因子与未来收益并非线性关系，但常呈现单调关系，此时 RankIC 更稳健。

### 4. 股票量化研究中的关键处理

> 中性化：指通过**回归**、**分层**或**标准化**等方法，剔除因子中不希望承受的系统性暴露（如行业、市值、风格），只保留更纯净的选股信号。包括
> - 市值中性化：剔除因子中的大盘股/小盘股暴露
> - 风格中性化：剔除如 Beta、动量、波动率、流动性、价值等风格暴露
> - 市场中性化：让组合整体对大盘涨跌不敏感，常见于多空策略
> - 板块/主题中性化：剔除某些板块、概念、赛道带来的系统偏差
> - 国家/区域中性化：多市场研究里剔除地区暴露
> - 时间/季节性中性化：去掉月份效应、节假日效应等时点偏差

- **行业中性化是什么**：
  - 指把因子中**由行业暴露带来的系统性差异剔除掉，只保留行业内部的相对选股信息**。
  - 常见做法包括行业内标准化（在每个行业内部单独做标准化，只比较行业内谁高谁低）、行业虚拟变量回归取残差（把行业哑变量放进回归模型，用残差作为剔除行业影响后的因子部分）、行业分层排序（先在各行业内部排序，再合并成全市场相对排名）。
  - 目的在于避免“其实是押行业，而不是选股”的伪因子效果。
- **为什么要做行业中性化**：
  - 防止某个因子只是行业权重的映射。
  - 提升不同阶段和不同市场环境下的稳定性。
  - 便于和市值中性化、风格中性化一起做纯因子暴露控制。
- **回测中如何避免未来函数**：
  - 特征值只能使用当时可获得的数据。
  - 财务数据必须考虑公告日/可见日，而不是报告期。
  - 标签构造和特征构造严格错开，例如用 `t` 时点特征预测 `t+1` 或更远收益。
  - 训练、调参、标准化都不能偷看未来样本。

#### 1. 因子构建、框架与解释

- **因子挖掘的一般流程**：
  - 从经济逻辑、文献复现或数据驱动出发提出**候选因子**
  - 做**数据清洗**、**去极值**、**缺失值处理**、**时点对齐**
  - 做**中性化、标准化、分层测试、IC 测试与样本外验证**
  - 最后再看**换手率**、**交易成本**、**稳定性**和**容量**
- **换手率公式**：
  - 在组合层面，常见定义是：
    $$
    turnover_t = \frac{\sum_i \left| w_{i,t} - w_{i,t-1}^{*} \right|}{2}
    $$

  - 其中 $w_{i,t-1}^{*}$ 表示考虑价格变化后的上一期实际权重
  - 在个股层面也常见成交额/流通市值、成交量/流通股本等口径，面试时一定要先说清口径
- **如何看待换手率因子**：
  - 它既可能反映**流动性**，也可能反映**注意力、博弈强度和短期情绪**
  - 单独看时，换手率高未必是好事，因为也可能只是**噪声交易多**
  - 更常见的做法是和收益反转、波动率、成交额、行业状态结合使用
- **如何看待市值因子**：
  - 市值因子是最经典的风格因子之一，本质上反映规模溢价与风险偏好
  - 它往往不是“阿尔法因子”，而更像一个必须识别和控制的基础暴露
  - 实务里通常要区分：你是主动利用它，还是先把它中性化掉
- **Barra 因子框架是什么**：
  - Barra 本质上是一个**多因子风险模型框架**，核心目标不是直接找阿尔法，而是把组合收益和风险拆解到一组可解释的系统性因子上。
  - 它通常把股票收益写成“**市场因子 + 行业因子 + 风格因子 + 特质收益**”的形式，即：个股收益中哪些来自整体市场、哪些来自行业暴露、哪些来自风格暴露、剩下多少是无法被这些公共因子解释的特质部分。
  - 常见风格因子包括：`Size`（规模）、`Beta`（市场敏感度）、`Momentum`（动量）、`Residual Volatility`（特质波动）、`Liquidity`（流动性）、`Growth`（成长）、`Value`（价值）、`Leverage`（杠杆）等。
  - 在实务里，Barra 的价值主要体现在四件事：`风险归因`（组合波动来自哪里）、`组合约束`（避免某些风格暴露过大）、`风格暴露控制`（做纯 alpha 而不是不小心押中了某个风格）、`业绩分解`（超额收益到底来自选股还是风格偏离）。
  - 可以把它理解成一个“风险坐标系”：先把每只股票和每个组合投影到一组统一的因子维度上，再讨论暴露、协方差、边际风险和风险预算。
  - **和 Fama-French 三因子的区别**：
    - `FF 三因子` 更偏**学术资产定价框架**，经典形式是市场因子 `MKT`、规模因子 `SMB`、价值因子 `HML`，核心问题是“这些公共因子能否解释平均收益截面”。
    - `Barra` 更偏**实务风险管理框架**，因子数量更多，定义更细，行业维度和风格维度更完整，重点是“如何解释组合风险并进行组合约束与归因”。
    - `FF 三因子` 更强调解释收益来源、检验因子溢价；`Barra` 更强调估计风险、控制暴露、服务组合构建。
    - `FF 三因子` 通常是较少几个宏观风格因子；`Barra` 往往包含大量行业因子和多个风格因子，工程实现上也更依赖协方差矩阵估计、暴露矩阵构建和日常更新。
  - 面试里更稳的总结是：**Fama-French 更像解释“为什么资产会有这样的平均收益”，Barra 更像回答“我的组合现在承担了什么风险、这些风险来自哪里”。**
- **某英文因子框架（非 Barra）怎么看**：
  - 如果面试时遇到没听清的英文框架，不要硬猜
  - 更稳的回答方式是：先问清它是偏风险模型、收益预测框架，还是因子库/信号库；然后再从“可解释性、稳健性、样本外表现、可交易性、是否容易**过拟合**”几个维度来评价
  - 这样即便名字没听清，也不会完全失分

#### 2. 数据清洗与分布处理

- **实习里的数据清洗通常包括**：
  - 缺失值处理
  - 异常值识别与去极值
  - 复权、停牌、涨跌停、重复值和时点对齐处理
  - 财务数据按公告日而非报告期对齐
  - 统一股票池、行业分类、交易日历和可交易状态
- **市值因子、股价因子为什么常常不服从正态**：
  - 市值通常呈明显**右偏长尾分布**，少数超大市值股票拉出很长右尾
  - 股价也受价格下界、分拆、壳资源、市场结构等影响，通常不是对称分布
  - 所以直接拿原值建模**容易被极端值主导**
- **日内 `high/low` 或振幅类因子的分布形态**：
  - 这类变量通常有边界约束、右偏、厚尾
  - 如果定义成 `high/low` 比值，通常下界在 `1` 左右，右尾较长
  - 如果定义成 `(high-low)/close`，也常表现为偏态且受极端波动影响明显
- **如何把这类因子处理得更接近正态**：
  - 先做**去极值**
  - 再做**对数变换**、Box-Cox、Yeo-Johnson，或基于排序的 inverse normal transform
  - 最后再做标准化
  - 重点是：要先改变分布形状，再做尺度调整
- **归一化 / 标准化 / 正态化的区别**：
  - **Min-Max 归一化只是缩放到固定区间，不改变分布形状**
  - **Z-score 标准化只是变成均值 0、方差 1，也不保证正态**
  - **正态化是通过对数变换、Box-Cox、Yeo-Johnson 或 rank-gauss 等方法，把数据分布主动变得更接近正态**
  - 所以严格说，**无论归一化还是标准化，都不能把非正态变量直接变成正态**
  - 如果面试官问“为什么可以变正态”，更严谨的回答是：真正起作用的是对数变换、Box-Cox 或 rank-gauss，而不是单纯的归一化或 Z-score
- **股票截面收益率的分布特点**：
  - 实务中通常并不严格服从**正态**，更接近尖峰厚尾、可能带偏度的分布
  - 极端值通常比正态分布下更多，因为会受个股事件、涨跌停、流动性冲击、行业共振等影响
  - 所以在截面建模时常要做 winsorize（把极端值截断到设定上下界，减少异常点影响）、robust 标准化（用中位数和 MAD 等稳健统计量替代均值和标准差做缩放）、分位数处理（按排序或分位区间重映射数据，弱化长尾和极端值干扰）

- **一句话理解数据清洗**：
  - 数据清洗不是“把数据弄好看”，而是把原始数据整理成**可计算、可对齐、可回测、无明显口径错误**的研究数据。
  - 在量化里，很多错误收益并不是策略本身有效，而是来自重复值、错位、未来函数、停牌处理错误或复权口径不一致。

- **数据清洗的一般流程**：
  - 先检查字段类型、时间索引、主键是否唯一。
  - 再处理缺失值、重复值、异常值和不可交易样本。
  - 然后统一复权口径、交易日历、股票池/合约池和公告日对齐方式。
  - 最后做去极值、标准化、中性化，并确认所有特征都只使用当时可见信息。

```text
数据清洗伪代码

输入：
  原始行情数据 raw_price
  原始基本面数据 raw_fundamental
  交易日历 trading_calendar
  股票池或合约池 universe

步骤 1：基础检查
  检查主键是否唯一，例如 (instrument, date)
  统一字段类型、时间格式、列名口径
  按 instrument 和 date 排序

步骤 2：过滤无效样本
  删除重复记录
  剔除退市、长期停牌、明显错误价格或成交量记录
  按研究口径限定 universe

步骤 3：处理缺失值和异常值
  对缺失值判断原因：
    如果是正常无交易，则标记不可交易
    如果是数据缺口，则选择填充、删除或单独标记
  对异常值做去极值：
    可使用 MAD、winsorize 或分位数截断

步骤 4：时点对齐
  行情数据对齐到统一交易日历
  财务数据按公告日/可见日向后生效
  所有特征使用 date=t 时点可获得的信息

步骤 5：口径统一
  统一前复权、后复权或等比复权口径
  统一行业分类、市值口径、收益率计算方式

步骤 6：特征预处理
  对因子做标准化或排序化
  必要时做行业中性化、市值中性化
  生成最终可用于研究的数据表 clean_data

输出：
  clean_data
  数据质量检查报告
```

#### 3. 分钟频数据与线性模型

- **分钟频数据怎么用**：
  - 构造日内波动率、振幅、量价相关、成交密度、尾盘效应等微观结构特征
  - 聚合成日频因子后参与截面选股
  - 或直接用于日内预测、执行优化、冲击成本评估
  - 使用时要特别注意噪声、撮合机制、缺失分钟和复权口径
- **多重共线性怎么理解**：
  - 指解释变量之间高度相关，导致回归系数不稳定、显著性扭曲、解释困难
  - 它不一定影响预测值，但会影响参数解释和模型稳定性
- **实际处理中如何应对多重共线性**：
  - 先看相关矩阵和 VIF
  - 再做删变量、合成变量、正则化（Ridge/Lasso）、主成分/PCA、正交化等
  - 若你项目里用了熵权法，也可以说它更像“多指标加权融合”，能减少多个强相关指标直接同时入模的问题，但它不是最经典的共线性处理工具

#### 4. 建模、算法与概统基础

- **模拟退火原理**：
  - 借鉴物理退火过程，高温时允许较差解被接受，从而跳出局部最优
  - 随着温度下降，接受差解的概率逐渐减小，最终收敛到较优解
  - 常用于组合优化、路径规划、参数搜索
- **XGBoost 与随机森林区别**：
  - 随机森林是 Bagging，树与树之间并行、主要靠随机采样和投票降方差
  - XGBoost 是 Boosting，树与树之间串行，每棵树都在修正前一轮误差
  - XGBoost 更强调拟合残差、正则化和损失优化；随机森林更强调稳健和抗过拟合
- **中心极限定理 / 大数定律的面试表达**：
  - 大数定律：样本均值最终逼近总体均值
  - 中心极限定理：样本均值经过标准化后趋于正态
  - 回答时别只背定义，最好补一句“一个管收敛，一个管分布”
- **如何用偏硬币构造公平游戏**：
  - 经典方法是 von Neumann trick
  - 连抛两次，只在出现 `HT` 或 `TH` 时记结果；规定 `HT` 为甲赢，`TH` 为乙赢；若是 `HH` 或 `TT` 则重来
  - 因为 `P(HT)=P(TH)=p(1-p)`，所以无论硬币偏不偏，双方概率都相等


### 因子研究入门



### 1. 因子研究到底在研究什么？

- 因子研究不是直接下单交易，而是先回答一个问题：某个特征值高的资产，未来表现会不会系统性更好或更差。
- 所以它更像“先验证一个想法”，而不是“先写一条交易规则”。
- 这也是为什么因子研究常常出现在正式策略开发之前。

### 2. 什么是因子？什么是标签？

- 因子（factor）：你拿来解释或预测未来收益的特征值
- 标签（label）：你真正想预测、想解释的目标结果
- 在这一节里：
  - `momentum_factor` 是因子
  - `next_return` 是标签

你可以先这样记：

- 因子是“已知信息”
- 标签是“未来结果”

常见误区：

- 把当前价格本身和因子混为一谈。价格是原始数据，因子通常是从数据加工出来的特征。
- 把未来收益也当成当前可见信息，会引入未来函数问题。

### 3. 什么是截面数据？为什么因子研究里总在讲“同一天多只股票”？

- 截面数据可以理解成：同一个时间点上，很多资产并排放在一起比较。
- 时间序列更关注“同一个资产随时间怎么变”；截面更关注“同一时点不同资产之间怎么比”。
- 因子研究里，很多问题本质上都是：同一天里，因子高的股票和因子低的股票，未来表现有没有差别。

极小例子：

```python
df = pd.DataFrame({
    "date": ["2025-03-31"] * 3,
    "symbol": ["A", "B", "C"],
    "factor": [0.9, 0.3, 0.6],
    "next_return": [0.03, -0.01, 0.01],
})
```

### 4. 为什么先排序、再排名？

- 排序是为了直观看看：因子高的样本，未来收益是不是整体更高。
- 排名是为了把“绝对值大小”转换成“相对位置”，方便后续做分组、分层、秩相关。
- 所以 `sort_values()` 和 `rank()` 虽然都和“顺序”有关，但用途不完全一样。

极小例子：

```python
sorted_df = df.sort_values("factor", ascending=False)
df["factor_rank"] = df["factor"].rank(ascending=False)
```

### 5. 什么叫分层（grouping）？为什么要分层？

- 分层就是把样本按因子值分成几组，比如高、中、低组。
- 这样做的目的，是看不同因子层级对应的未来收益是否有明显差异。
- 如果高因子组长期优于低因子组，通常说明因子有一定研究价值。

极小例子：

```python
df["group"] = pd.qcut(df["factor"], q=3, labels=["low", "mid", "high"])
```

相关概念：

- 排名：先得到顺序
- 分层：再按顺序切成几组
- 分组统计：最后比较各组表现

常见误区：

- 样本太少时硬分太多组，结果不稳定甚至报错。
- 只看分组标签，不检查每组里到底有多少样本。

### 6. `groupby()` 在因子研究里是在做什么？

- `groupby()` 本质上是在说：请按某个分组标签，把样本拆开分别统计。
- 在因子研究里，它经常用来比较高因子组、低因子组的平均未来收益。

极小例子：

```python
group_return = df.groupby("group")["next_return"].mean()
```

本节怎么用：

- 它是在把“分层结果”变成真正可比较的数字结果。

### 7. 什么是 IC？为什么它重要？

- IC 可以先粗略理解成：因子值和未来收益之间的相关性。
- 如果因子越高，未来收益整体越高，那么 IC 往往偏正。
- 如果长期稳定为正或为负，通常说明这个因子和未来收益之间可能存在稳定关系。

极小例子：

```python
ic = df["momentum_factor"].corr(df["next_return"])
```

相关概念：

- IC：通常看线性相关
- Rank IC：通常先做排名再看相关，对极端值不那么敏感

常见误区：

- 只看某一天的 IC 就下结论。真实研究更关心很多期的平均 IC 是否稳定。

### 8. 为什么因子研究要看“多期截面”？

- 因为单天结果可能只是巧合。
- 真实研究不会因为某一天看起来关系不错，就认定因子有效。
- 所以更常见的做法是：按日期分组，算每期 IC，再看长期平均和稳定性。

极小例子：

```python
daily_ic = multi_df.groupby("date").apply(
    lambda x: x["value_factor"].corr(x["next_return"]),
    include_groups=False
)
```

- 这一节开始，你会从“直接做策略”转向“先研究一个特征有没有预测力”。
- 后面统计回归、机器学习章节，其实都是在用更系统的方法回答类似问题：特征和未来结果之间到底有没有稳定关系。

### 风险管理与组合分析



### 1. 为什么学到这里一定要看“组合”而不只是看单个策略？

- 因为真实资金通常不会只押在一个资产或一条信号上。
- 当你把多个资产放在一起时，结果不只是“收益相加”这么简单，风险结构也会跟着变化。
- 所以这一节的重点，是把视角从“单资产/单策略”切换到“整体组合”。

### 2. 什么是组合？什么是权重？

- 组合（portfolio）：把多个资产按一定比例放在一起形成的整体
- 权重（weight）：每个资产在组合里占多大比例
- 比如 `[0.4, 0.3, 0.3]` 表示：
  - 第一个资产占 40%
  - 第二个资产占 30%
  - 第三个资产占 30%

你可以先这样记：

- 资产回答“买什么”
- 权重回答“各买多少”

### 3. 为什么这里要把权重写成 `np.array(...)`？

- 因为组合计算本质上很适合用数组和向量运算。
- 把权重写成数组后，就能方便地和资产收益做点乘。
- 这也是 `numpy` 在线性代数和组合分析里特别常见的原因。

极小例子：

```python
weights = np.array([0.4, 0.3, 0.3])
```

### 4. `dot(weights)` 到底在干什么？

- `dot` 可以先理解成“对应位置相乘，再全部加起来”。
- 对组合收益来说，它正好对应：
  - 每个资产收益乘以自己的权重
  - 再把它们加总
- 所以点乘是组合收益最核心的数学表达之一。

极小例子：

```python
returns_df["portfolio_return"] = asset_returns.dot(weights)
```

常见误区：

- 以为组合收益就是简单平均。其实要看你给每个资产分了多少权重。

### 5. 为什么有了组合收益之后，还要再算组合净值？

- 因为组合收益是“每天赚多少”，而净值是“整段资金曲线最后走成什么样”。
- 这和前面单策略的逻辑完全一样，只是对象从“单个收益序列”变成了“组合收益序列”。

极小例子：

```python
returns_df["portfolio_nav"] = (1 + returns_df["portfolio_return"]).cumprod()
```

### 6. 相关性为什么是组合分析的核心？

- 因为组合不是只看每个资产自己好不好，还要看它们之间是不是总在一起涨跌。
- 如果两个资产高度正相关，看起来你买了两个，其实风险可能还是同一类。
- 如果相关性较低，组合更可能获得分散化好处。

极小例子：

```python
corr_matrix = asset_returns.corr()
```

你可以先这样理解：

- 相关性高：一起涨跌，更像“同一队人”
- 相关性低：走势差异更大，分散化更可能有效

常见误区：

- 以为资产数量一多就一定更安全。关键不是数量本身，而是它们之间的关系。

### 7. 波动率和最大回撤为什么在组合里仍然重要？

- 因为组合的目标从来不只是“收益高”，还包括“整体风险能不能接受”。
- 单个资产的波动和组合的波动不一定一样。
- 所以组合层面必须重新看波动率和回撤，而不是只看单资产表现。

### 8. 什么叫仓位控制？为什么它本质上是在控制风险？

- 仓位控制可以先理解成：你愿意让多少资金暴露在市场风险里。
- 仓位越高，收益放大，波动和回撤通常也会放大。
- 所以仓位控制不只是“保守一点”，而是在主动调节风险暴露。

极小例子：

```python
returns_df["half_position_return"] = returns_df["portfolio_return"] * 0.5
```

### 9. 为什么要比较等权组合和集中组合？

- 因为这是理解“分散化”最直观的对比方式。
- 等权组合表示资金分得比较均匀。
- 集中组合表示大部分权重压在少数资产上。
- 这种对比能帮助你直观感受到：仓位集中往往意味着风险也更集中。

极小例子：

```python
equal_weights = np.array([1/3, 1/3, 1/3])
concentrated_weights = np.array([0.8, 0.1, 0.1])
```

### 10. 为什么这一节特别强调变量命名？

- 因为到组合层面后，很容易混淆“资产层面”和“组合层面”。
- `asset_returns`、`portfolio_return`、`portfolio_nav` 这些名字，其实是在帮你随时提醒自己：现在讨论的是哪一层对象。
- 当分析对象开始变多时，清楚命名本身就是降低错误的重要工具。

- 这一节让你开始理解：真正的资金管理往往发生在组合层面。
- 最后一节项目工程化时，你会进一步看到：组合、风险、回测、评估这些模块，最终都要被组织进更清晰的项目结构里。
