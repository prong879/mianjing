这里的两个常见框架可以先有一个直观认识：

- **Backtrader**：Python 生态里非常常见的**策略研究与历史回测框架**，适合快速验证交易逻辑、指标、手续费设置和绩效分析。
- **vn.py**：国内量化交易里很常见的**事件驱动式交易框架**，更偏向真实交易接入，常用于对接行情、下单、风控和 CTA 策略运行。
- **一句话区分**：`Backtrader` 更偏**研究/回测**，`vn.py` 更偏**实盘/交易系统**。

如果面试官继续追问“你熟悉它们，那里面常用什么”，最稳的回答不是背很多接口名，而是把**常用对象、常用函数和典型流程**讲清楚：

- **Backtrader 常用对象 / 函数**：
  - `bt.Cerebro()`：回测总控，负责装配数据、策略、资金和分析器。
  - `cerebro.adddata(data)`：添加行情数据。
  - `cerebro.addstrategy(MyStrategy)`：添加策略类。
  - `cerebro.broker.setcash(...)`：设置初始资金。
  - `cerebro.broker.setcommission(...)`：设置手续费。
  - `cerebro.run()`：启动回测。
  - `cerebro.plot()`：绘制回测图。
  - `bt.indicators.SimpleMovingAverage(...)`、`bt.indicators.CrossOver(...)`：常见指标和交叉信号。
  - `self.buy()`、`self.sell()`、`self.close()`：常见下单 / 平仓接口。
  - `__init__()`、`next()`：最核心的两个策略函数，前者初始化指标，后者按 Bar 执行逻辑。

- **Backtrader 常见流程**：
  - 准备 `Pandas DataFrame` 数据。
  - 转成 `bt.feeds.PandasData`。
  - 写一个继承 `bt.Strategy` 的策略类。
  - 在 `__init__()` 里定义指标，在 `next()` 里写买卖规则。
  - 用 `Cerebro` 挂载数据、策略、资金和手续费。
  - 运行回测，最后看净值、交易记录和图表。

- **vn.py 常用对象 / 函数**：
  - `CtaTemplate`：CTA 策略基类，写策略通常从继承它开始。
  - `on_init()`：初始化策略、加载历史数据。
  - `on_start()`：策略启动。
  - `on_tick(tick)`：收到逐笔 / 快照行情时触发。
  - `on_bar(bar)`：收到一根 K 线后触发，是中低频 CTA 最常写逻辑的地方。
  - `BarGenerator`：把 `Tick` 合成 `Bar`，或把小周期 Bar 合成更大周期 Bar。
  - `ArrayManager`：缓存历史 K 线并计算技术指标，如均线、`MACD`、布林带。
  - `buy()`、`sell()`、`short()`、`cover()`：分别对应开多、平多、开空、平空。
  - `self.load_bar(...)`：加载历史 K 线预热指标。
  - `self.put_event()`：更新界面状态。

- **vn.py 常见流程**：
  - 继承 `CtaTemplate` 定义策略类和参数。
  - 在 `on_init()` 中加载历史数据并预热指标。
  - 在 `on_tick()` 中把 Tick 推给 `BarGenerator`。
  - 在 `on_bar()` 中用 `ArrayManager` 更新指标并生成交易信号。
  - 调用 `buy/sell/short/cover` 下单。
  - 在实盘或仿真环境里观察成交、持仓、风控和日志。

- **面试里一句话区分工作流**：
  - `Backtrader` 更像“拿历史数据做策略研究和回测验证”。
  - `vn.py` 更像“接交易接口、收实时行情、驱动策略运行和下单执行”。

对应的使用流程也可以直接用伪代码来记：

```text

输入：
  历史行情数据 df

步骤 1：准备数据
  读取历史行情

步骤 2：定义策略类
  class MyStrategy(bt.Strategy):
    在 __init__() 中：

  cerebro = bt.Cerebro()
```

```text
vn.py 使用流程伪代码

输入：
  实时行情或历史行情回放
  策略参数 params

步骤 1：定义 CTA 策略类
  class MyCtaStrategy(CtaTemplate):
    定义参数、变量
    创建 BarGenerator
    创建 ArrayManager

步骤 2：初始化阶段
  on_init():
    self.load_bar(n)          # 加载历史 K 线预热指标
    初始化日志和状态

步骤 3：启动阶段
  on_start():
    开始接收实时行情

步骤 4：行情驱动
  on_tick(tick):
    把 tick 推给 BarGenerator

  on_bar(bar):
    把 bar 更新到 ArrayManager
    如果历史数据不足：
      return

    计算均线、MACD、布林带或突破指标

    如果没有持仓且满足开多条件：
      buy(price, volume)
    如果没有持仓且满足开空条件：
      short(price, volume)
    如果持有多头且满足平仓条件：
      sell(price, volume)
    如果持有空头且满足平仓条件：
      cover(price, volume)

    self.put_event()          # 更新界面和状态

步骤 5：执行与风控
  订单进入撮合
  接收成交回报
  更新持仓、资金、日志和风控状态

  持仓、成交、策略状态、日志、净值表现
```

量化交易里还经常会出现**高频 / 中频 / 低频 / 中低频**这些词，面试官有时不会专门定义，而是默认你知道它们在说什么。更稳的理解方式是：**这不是按某个绝对天数硬切，而是按数据频率、持有周期、交易频率、执行系统依赖程度综合区分**。

- **高频交易（High-Frequency Trading, HFT）**：
  - 更正式的定义通常强调：**高速度、高换手、高订单提交 / 撤单比、依赖高频数据和电子化交易工具**。
  - 实务上常见是用 **Tick 级、逐笔成交、盘口 / Level-2** 数据做信号。
  - 持仓时间往往极短，可能是秒级、毫秒级，很多策略**不隔夜**。
  - 对延迟极其敏感，往往要考虑撮合速度、网络延迟、柜台接口、共址、订单队列位置等问题。
  - 典型策略包括：做市、超短统计套利、盘口微结构信号、事件驱动抢跑等。

- **中频交易（Medium-Frequency Trading, MFT）**：
  - 一般指介于高频和低频之间的策略。
  - 常见使用 **分钟级到小时级** 数据，也可能用日内信号。
  - 持有周期常见为**日内到数天**。
  - 对执行有一定要求，但不像高频那样把“几毫秒快一点”当成核心竞争力。
  - 常见策略包括：日内趋势、短周期动量、短周期反转、配对交易、部分统计套利。

- **低频交易（Low-Frequency Trading, LFT）**：
  - 一般用 **日线、周线甚至月线** 数据生成信号。
  - 持有周期通常是**数天、数周、数月**，甚至更长。
  - 核心竞争力通常不在极致执行速度，而在**研究逻辑、因子构建、资产配置、基本面理解和风控**。
  - 常见策略包括：多因子选股、中长期趋势跟踪、基本面 CTA、资产配置、低换手组合管理。

- **中低频**：
  - 这是实务里特别常见的说法，通常不是严格学术分类，而是把**不依赖超低延迟基础设施**、持有周期相对更长的策略归在一起说。
  - 在招聘语境里，“中低频”通常意味着：
    - 以 `Python`、`Pandas`、因子研究、回测分析为主
    - 更看重研究逻辑、统计检验、样本外稳定性
    - 不要求你像高频那样深入撮合引擎、微秒级延迟优化和 `C++` 性能工程

- **这些词到底按什么划分**：
  - **第一维：数据频率**  
    高频常看 Tick / 盘口；中频常看分钟 / 小时；低频常看日线及以上。
  - **第二维：持有周期**  
    高频偏秒级到日内；中频偏日内到数天；低频偏数天到数月。
  - **第三维：执行依赖程度**  
    高频高度依赖低延迟执行；低频更依赖信号逻辑本身。
  - **第四维：收益来源**  
    高频更多来自微观结构、价差和流动性；中低频更多来自趋势、因子、基本面和中周期错价。

- **几个很容易混淆的点**：
  - **高频不等于高换手，低频也不一定低换手**。频率更强调“你依赖什么时间尺度的信息”和“你对执行系统的依赖程度”。
  - **分钟级策略不一定就是高频**。很多 `1min` 或 `5min` Bar 上的 CTA 更常被归到中频或中低频。
  - **是否隔夜不是唯一标准**。有些日内策略是中频，有些超短日内盘口策略才更接近高频。

- **放到你这份岗位语境里怎么理解**：
  - 你现在准备的是**期货 CTA / 量化研究实习**，大概率更接近**中低频研究岗**。
  - 这类岗位通常更关心：
    - 因子定义是否清楚
    - 数据清洗和回测是否严谨
    - 是否理解换月、基差、期限结构、成本和风控
  - 而不是一上来就要求你会做真正的毫秒级高频交易系统。

- **和 `Backtrader / vn.py` 的关系**：
  - `Backtrader` 更常用于**中低频策略研究与回测**。
  - `vn.py` 可以覆盖更广，但你文档里这种 `on_bar` 驱动的 CTA 示例，更偏**中低频 CTA**。
  - 真正高频更常依赖 Tick/盘口数据、低延迟撮合和更底层的执行系统。

*面试里一句话概括*：
- **高频 / 中频 / 低频本质上是在区分策略挖掘信息的时间尺度和对执行系统的依赖程度：高频更靠 Tick、低延迟和微观结构，中低频更靠分钟到日线数据、研究逻辑和风控框架。**

> `CTA`：实务里通常指以**期货等衍生品**为主要交易对象、通过规则或模型进行多空交易和风险控制的系统化策略；原始缩写来自 `Commodity Trading Advisor`。
