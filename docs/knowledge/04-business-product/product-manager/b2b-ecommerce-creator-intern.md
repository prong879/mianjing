# B端产品实习：电商达人方向

> 适用岗位：B端产品实习生、电商达人产品、达人营销产品、商家/运营工具产品、AI产品实习。  
> 核心判断：这个岗位不是单纯运营，也不是只画原型的产品岗，而是**电商达人业务 + B端工作流 + 一线调研 + AI提效**的交叉岗位。

## 一、JD 快速拆解

### 1. 岗位一句话

协助产品经理面向电商达人行业，深入运营、电商小二等一线场景，梳理达人业务工作流，发现低效、重复、可标准化的环节，并把这些问题沉淀成需求池、原型、PRD和可落地的AI或B端工具能力。

### 2. 三类核心职责

| JD 原文 | 面试官真正想看什么 | 你要准备的证据 |
| --- | --- | --- |
| 需求分析与规划，原型设计及PRD撰写 | 是否懂产品基本功，能不能把模糊问题写成研发可做的需求 | PRD结构、用户故事、流程图、优先级、验收标准 |
| 客户访谈、跟岗调研、流程梳理、AI可介入环节 | 是否能下现场，不怕脏活，能从一线流程里抽象需求 | 访谈提纲、跟岗方法、流程图、痛点分层、AI场景判断 |
| 与研发、运营协作，推进项目上线 | 是否能跨角色沟通，理解B端产品落地不是只交文档 | 排期、评审、需求变更、灰度、验收、上线复盘 |

### 3. 四类能力要求

| 能力 | 准备重点 |
| --- | --- |
| 电商业务理解 | 达人、商家、MCN、平台小二、运营、消费者之间的关系 |
| B端产品能力 | CRM、工单、IM、知识库、权限、流程、审批、看板 |
| AI产品意识 | RAG、智能客服、知识库问答、工单分类、内容生成、质检、推荐 |
| 数据分析能力 | SQL、漏斗、效率指标、采纳率、转人工率、解决率、满意度 |

## 二、业务背景：电商达人是什么

### 1. 关键角色

| 角色 | 目标 | 典型诉求 |
| --- | --- | --- |
| 达人 | 通过短视频、直播、图文带货变现 | 找合适商品、提高转化、减少履约和售后风险 |
| 商家 | 通过达人获取流量和成交 | 找匹配达人、控ROI、看合作效果 |
| MCN/服务商 | 批量管理达人和商业合作 | 达人管理、合同排期、数据复盘 |
| 平台小二/运营 | 维护达人生态，撮合交易，提升GMV和内容质量 | 批量管理、问题处理、策略运营、规则宣导 |
| 消费者 | 通过内容发现商品并完成购买 | 商品可信、价格合适、售后有保障 |

### 2. 达人业务链路

```text
商家提出推广诉求
  -> 平台或服务商筛选达人
  -> 达人选品与确认合作
  -> 内容生产或直播排期
  -> 商品挂车 / 链接配置 / 佣金设置
  -> 内容发布或直播带货
  -> 交易转化与履约
  -> 售后、违规、投诉处理
  -> 数据复盘与下一轮合作
```

### 3. B端产品机会

电商达人业务的复杂点在于角色多、流程长、沟通频繁、规则变化快。产品机会通常来自四类低效：

1. **信息分散**：达人资料、商家需求、历史合作、规则文档散在多个系统或群聊里。
2. **人工判断多**：达人匹配、风险识别、优先级排序依赖运营经验。
3. **重复沟通多**：常见问题、规则解释、工单回复、合作确认反复发生。
4. **复盘不闭环**：活动效果、问题原因、达人表现没有沉淀成可复用知识。

## 三、这个岗位最该准备的知识点

### 1. B端产品基本功

你要能讲清楚：

- B端产品重视业务流程、效率、权限、安全、数据一致性，C端更重体验、增长和心智。
- B端需求往往来自组织目标和一线流程，不是只看单个用户喜好。
- PRD要写清目标、范围、角色、流程、规则、异常、权限、验收标准。
- 原型不是重点，重点是把业务规则和边界讲清楚。

面试表达：

> B端产品的核心不是把页面画漂亮，而是把复杂流程产品化。比如电商达人场景里，运营、小二、商家、达人各自目标不同，我需要先梳理角色、任务、流转节点和异常，再判断哪些步骤适合系统化、自动化或AI辅助。

### 2. 电商达人业务知识

你要准备这些概念：

| 概念 | 面试可用解释 |
| --- | --- |
| 达人带货 | 达人通过内容或直播影响消费者购买，平台通过佣金、广告、服务费等方式变现 |
| 达人匹配 | 根据品类、人群、内容风格、历史GMV、转化率、粉丝画像、履约风险等匹配商家需求 |
| 选品 | 达人选择适合自己人设和粉丝的商品，关注佣金、价格力、库存、口碑、售后 |
| 佣金 | 商家给达人或机构的推广分成，是达人合作的重要决策因素 |
| 平台小二 | 平台侧运营角色，负责规则、撮合、活动、问题处理和生态治理 |
| MCN | 管理多个达人的机构，常承担商务、排期、内容、数据复盘 |
| 内容电商 | 通过短视频、直播、图文内容激发购买，而不是用户主动搜索购买 |

### 3. 一线调研和客户访谈

JD 特别强调“深入运营、电商小二一线工作场景”，所以一定会问调研方法。

准备框架：

```text
明确目标
  -> 选角色：运营、小二、商家、达人、客服
  -> 做访谈：问目标、流程、工具、痛点、异常、指标
  -> 跟岗观察：记录真实操作，不只听口述
  -> 还原流程：画泳道图或流程图
  -> 提炼痛点：按频率、影响、成本、可解决性分层
  -> 形成需求池：写用户故事、业务价值、优先级
  -> 回访验证：让一线确认是否真实
```

访谈问题模板：

| 维度 | 可以问的问题 |
| --- | --- |
| 目标 | 你这个岗位最核心的KPI是什么？每天最重要的任务是什么？ |
| 流程 | 从接到商家需求到完成达人合作，中间有哪些步骤？ |
| 工具 | 你现在用哪些系统、表格、群聊或人工记录？ |
| 痛点 | 哪一步最耗时？哪一步最容易出错？哪类问题最常重复？ |
| 异常 | 遇到达人爽约、商品库存不足、佣金争议、违规投诉时怎么处理？ |
| 数据 | 你会看哪些指标判断达人合作效果？ |
| AI机会 | 哪些内容是重复判断、重复生成、重复查询，可以交给AI辅助？ |

### 4. AI产品和大模型应用

这个岗位不会要求你像算法工程师一样讲Transformer细节，但要懂“AI能做什么、不能做什么、怎么评估”。

必须掌握：

| 知识点 | 面试回答口径 |
| --- | --- |
| RAG | 先从知识库、规则、FAQ、历史工单中检索相关内容，再让大模型基于真实资料回答，降低幻觉 |
| Prompt | 用角色、任务、输入、输出格式、约束和示例控制模型输出 |
| Agent | 能拆步骤、调工具、读取数据并完成多步任务的系统，不只是单轮问答 |
| 知识库 | 平台规则、达人政策、FAQ、SOP、历史优秀回复的结构化沉淀 |
| 幻觉 | 大模型编造内容，B端场景必须用检索、引用、人工确认和规则兜底降低风险 |
| 人机协同 | AI先做草稿、分类、摘要、推荐，关键决策由人确认 |

电商达人场景里的AI机会：

| 场景 | AI可做什么 | 需要注意 |
| --- | --- | --- |
| 规则问答 | 小二或达人问规则时，AI基于知识库回答并给出处 | 不能编造政策，必须引用来源 |
| 工单分类 | 自动识别达人入驻、佣金、违规、履约、售后等问题类型 | 低置信度转人工 |
| 工单回复草稿 | 根据历史案例和规则生成回复建议 | 人工确认后发送 |
| 访谈纪要 | 自动整理访谈录音或笔记，提取痛点和需求 | 保护隐私，关键结论人工复核 |
| 达人匹配 | 根据商家品类、预算、人群推荐达人候选 | 不能只看粉丝量，要结合转化和风险 |
| 活动复盘 | 自动汇总GMV、转化、点击、退款、投诉等指标并生成复盘 | 指标口径要统一 |
| 知识库治理 | 根据高频问题发现缺失知识，推动规则文档更新 | 要有版本控制和审核 |

### 5. SQL和数据分析

岗位写了“掌握SQL或基础数据分析优先”，至少要准备电商和B端常见指标。

核心指标：

| 指标 | 含义 |
| --- | --- |
| GMV | 成交总额，衡量交易规模 |
| 订单数 | 成交订单量 |
| 转化率 | 从曝光、点击、进店、下单到支付的转化 |
| CTR | 点击率，点击 / 曝光 |
| CVR | 转化率，成交 / 点击或成交 / 曝光 |
| 客单价 | GMV / 订单数 |
| 退款率 | 退款订单或金额占比 |
| 投诉率 | 投诉量 / 订单量或服务量 |
| 达人合作成功率 | 成功合作数 / 邀约数 |
| 工单解决率 | 已解决工单 / 总工单 |
| 转人工率 | 转人工会话 / AI会话 |
| AI采纳率 | 人工采纳AI建议数 / AI生成建议数 |
| 平均处理时长 | 从问题进入到解决的平均耗时 |

常见SQL准备方向：

- 按达人、商家、品类统计GMV和订单数。
- 计算达人合作转化率、退款率、投诉率。
- 找出近7天高频工单问题。
- 按问题类型统计平均处理时长和解决率。
- 对比AI上线前后工单处理时长变化。

## 四、可能被问的问题

### 问题1：你怎么理解这个岗位？

回答要点：

1. 这是面向电商达人行业的B端产品实习岗位。
2. 工作重点是深入运营、小二等真实工作流，把一线问题转化为产品需求。
3. AI不是为了炫技，而是嵌入高频、重复、可标准化的环节，提升效率和质量。
4. 最终要通过PRD、原型、需求池和项目协同推动上线。

口播版：

> 我理解这个岗位的核心，是把电商达人业务里运营和小二的工作流产品化。它不是单纯画原型，也不是纯运营执行，而是要去一线看真实流程，比如达人撮合、规则答疑、工单处理、活动复盘中哪些环节高频、重复、容易出错，再判断是否适合通过系统能力或AI能力提效。最后要把问题沉淀成需求池，写清优先级、PRD和验收标准，协同研发和运营落地。

### 问题2：为什么你适合这个岗位？

回答要点：

- 金融 + 计算机双背景，有业务理解和技术沟通基础。
- 做过转债多因子系统产品化，能把研究员工作流拆成数据输入、指标计算、结果展示、复盘输出。
- 熟悉Python、MySQL、PRD和可视化，符合数据分析和B端工具要求。
- 做过AI Agent项目和AI应用半月报，对AI如何嵌入业务提效有理解。
- 虽然不是电商出身，但能快速学习行业流程，并用结构化方法补齐业务知识。

口播版：

> 我觉得匹配主要有三点。第一，我有金融和计算机双背景，做过Python、MySQL和可视化系统，能和研发沟通数据、接口和实现边界。第二，我在华福证券实习时做过投研工作流产品化，把研究员的因子分析和复盘流程拆成数据输入、指标计算、结果展示和复盘输出，也写过PRD，这和B端产品的流程梳理很像。第三，我做过多Agent和ETF监控项目，也长期跟踪AI Agent应用，理解AI更适合做规则问答、摘要、分类、草稿生成和复核，而不是替人做高风险最终决策。电商业务我会提前补齐达人、商家、小二和MCN链路，用调研方法快速进入场景。

### 问题3：如果让你调研电商小二的工作流，你会怎么做？

回答框架：

1. 明确调研目标：是提效、降错、找AI场景，还是优化某个具体流程。
2. 选样本：覆盖资深小二、新人小二、运营主管、客服或商家。
3. 做半结构化访谈：问任务、流程、工具、痛点、指标、异常。
4. 跟岗观察：记录真实操作路径、系统切换、复制粘贴、人工判断点。
5. 画泳道图：区分运营、小二、商家、达人、系统的动作。
6. 分析机会：高频、重复、规则明确、容错率高的环节优先AI化。
7. 输出需求池：按影响范围、频率、实现成本和风险排序。

口播版：

> 我会先明确调研目标，比如是要降低工单处理时长，还是发现AI可介入环节。然后选不同角色和经验层级的小二、运营、客服做访谈，同时跟岗看真实操作，因为B端用户口述和实际操作常常不一样。记录时我会关注他们在哪些系统间切换，哪些信息要反复查，哪些话术要重复写，哪些判断依赖经验。调研后我会画泳道图，还原角色和系统之间的流转，再把痛点按频率、影响、实现成本和风险分层，最后沉淀成需求池和优先级建议。

### 问题4：你怎么判断一个环节是否适合AI介入？

回答框架：

| 判断维度 | 适合AI | 不适合AI |
| --- | --- | --- |
| 频率 | 高频重复 | 低频偶发 |
| 输入 | 文本、规则、历史案例丰富 | 信息缺失或高度依赖线下判断 |
| 输出 | 摘要、分类、推荐、草稿、问答 | 最终审批、强合规决策、资金结算 |
| 容错 | 错了可人工修正 | 错了会造成资损或合规事故 |
| 评估 | 能用准确率、采纳率、时长衡量 | 无法定义好坏 |

口播版：

> 我不会为了AI而AI，会先看这个环节是否高频、重复、文本或知识密集，是否有历史数据和规则可以支撑，以及出错后能不能由人工修正。比如规则问答、工单分类、回复草稿、访谈纪要、复盘摘要都比较适合AI辅助。但像佣金结算、违规最终处罚、大额资源分配这类高风险决策，AI最多做建议，最终要人确认。评估上我会看准确率、采纳率、转人工率、平均处理时长和满意度。

### 问题5：如果要做一个“电商达人运营AI助手”，你会怎么设计MVP？

MVP目标：

先解决运营和小二最常见的规则查询、工单分类、回复草稿问题，不一开始做大而全的智能运营平台。

核心功能：

1. **知识库问答**：基于平台规则、达人政策、FAQ回答问题，附引用来源。
2. **工单自动分类**：识别入驻、佣金、履约、违规、售后等类型。
3. **回复草稿生成**：根据问题类型和知识库生成回复建议。
4. **人工采纳与修改**：AI不直接发送，人工确认后使用。
5. **Bad Case反馈**：运营可标记答案错误，进入知识库优化。

关键指标：

- AI答案准确率。
- 回复草稿采纳率。
- 平均工单处理时长下降比例。
- 转人工率。
- 一线运营满意度。

口播版：

> 我会先做一个克制的MVP，不做大而全的运营平台。第一期聚焦运营和小二最高频的规则查询和工单处理。用户输入问题后，系统从达人政策、平台规则、FAQ和历史工单里检索信息，再生成可引用来源的回答；对于工单，先自动分类，再给出回复草稿，但不直接发送，必须由人工确认。上线后看准确率、采纳率、平均处理时长和转人工率。如果这些指标证明有效，再扩展到达人匹配和活动复盘。

### 问题6：怎么给电商达人业务设计指标体系？

回答框架：

```text
平台目标：交易规模和生态健康
  -> 供给：达人数量、活跃达人、优质达人占比
  -> 撮合：商家需求数、达人邀约数、合作成功率
  -> 转化：曝光、点击、成交、GMV、CVR、客单价
  -> 质量：退款率、投诉率、违规率、履约时效
  -> 效率：工单处理时长、自动解决率、AI采纳率
```

口播版：

> 我会分业务结果和过程效率两层。业务结果看GMV、订单数、转化率、客单价，也要看退款率、投诉率和违规率，避免只追交易规模。过程效率看达人邀约到合作的转化、商家需求响应时长、小二工单处理时长、AI建议采纳率。达人生态还要看活跃达人、优质达人占比和不同品类供给是否健康。

### 问题7：你如何做需求优先级排序？

回答框架：

可以用 RICE 或“影响范围、痛点频率、业务价值、实现成本、风险”排序。

| 维度 | 说明 |
| --- | --- |
| Reach | 影响多少运营、小二、达人或商家 |
| Impact | 对效率、GMV、风险或体验的影响 |
| Confidence | 调研和数据证据是否充分 |
| Effort | 研发、数据、运营配置成本 |
| Risk | 是否有合规、资损、误判风险 |

口播版：

> 我会先把需求池里的问题统一成用户故事，再按影响范围、发生频率、业务价值、实现成本和风险排序。比如每天重复上百次的规则问答和工单分类，影响面大、规则明确、风险可控，优先级会高；而复杂达人匹配虽然价值大，但数据依赖和误判风险更高，可以先做推荐候选和人工确认，不直接自动决策。

### 问题8：AI上线后怎么评估效果？

回答要点：

- 业务效率：平均处理时长、自动解决率、人工节省时间。
- 质量：答案准确率、幻觉率、投诉率、Bad Case占比。
- 使用：AI调用量、采纳率、留存、活跃用户数。
- 成本：单次调用成本、节省人力成本、ROI。
- 风险：错误回答、违规输出、敏感信息泄露。

口播版：

> 我会从效率、质量、使用和风险四类看。效率看平均处理时长是否下降，自动解决率是否提升；质量看人工抽检准确率、幻觉率和Bad Case；使用看小二是否真的采纳AI建议，而不是上线没人用；风险看是否出现错误政策回答或敏感信息问题。B端AI产品一定要算账，如果节省的人力时间覆盖不了调用和维护成本，就说明场景价值还不够。

## 五、场景题准备

### 场景1：运营说“每天很多达人问规则，太浪费时间”，你怎么办？

思路：

1. 先量化：每天多少问题，集中在哪些规则，处理时长多少。
2. 归类：入驻、佣金、违规、活动、售后、结算。
3. 盘知识：规则文档、FAQ、历史回复是否完整。
4. 做MVP：知识库问答 + 来源引用 + 人工反馈。
5. 评估：准确率、采纳率、转人工率、处理时长。

### 场景2：达人匹配商家的转化率低，怎么分析？

拆解：

- 商家需求是否清晰：品类、预算、目标人群、佣金、时间。
- 达人画像是否完整：粉丝画像、内容风格、历史转化、履约质量。
- 匹配规则是否合理：只看粉丝量还是看ROI、退款、投诉。
- 沟通链路是否顺畅：邀约触达率、回复率、确认率。
- 商品是否有竞争力：价格力、库存、佣金、口碑、售后。

可能方案：

- 标准化商家需求表单。
- 建立达人标签体系。
- 增加达人推荐理由和风险提示。
- 对匹配结果做AB测试和复盘。

### 场景3：小二抱怨系统不好用，但说不清哪里不好，怎么办？

方法：

- 不直接问“你想要什么功能”，而是让TA演示一天工作。
- 记录系统切换、等待、重复录入、复制粘贴、人工判断。
- 标注每一步耗时和异常。
- 把问题分为流程问题、信息问题、权限问题、系统性能问题、组织规则问题。
- 用低保真原型或流程改造方案回访验证。

**问题：** 「需求目录」是怎么设计的？

**问题：** 请分两方面回答：（1）指标体系最终结构是什么，一层层拆解有哪些因子；（2）用了哪些技术解决这些问题。

**答案：**  
（1）**指标体系：** 首先确定北极星指标，它是最能代表当前业务核心目标的关键衡量标准，通常能够直接反映产品或团队最想达成的长期成果。例如，在该场景下，北极星指标可以是「当日需处理的异动 ETF 数量 / 覆盖率」，或者在投研场景中的「日报完整性」。北极星指标的特点是聚焦、易衡量且和业务价值紧密相关。接下来，将北极星指标拆解为易于落地和监控的子指标，包括流量指标（如有多少 ETF/成分股进入候选）、质量指标（如异常命中率、误报率）、效率指标（如人工处理耗时下降幅度等）。进一步细化到因子层，比如基础行情（价量）、技术指标（均线、RSI、布林带等）、团队自建因子（动量/反转等），必要时加入舆情数据（公告、研报标签等）。在目录上需明确每个指标的统计口径、计算频率及其业务解释，以便于研发和业务团队之间充分对齐、达成一致。
（2）**技术：** 数据落在 MySQL，批量任务或脚本算因子，Flask（你说得快也可用 FastAPI）提供页面和服务接口；可视化交互便于复核；AI 部分只做解释或摘要，与结构化筛选结果解耦，方便回溯对错。

**问题：** 假设你是小二，负责的主播近期直播 GMV 下降，你会怎么拆解？

**答案：** 先做三件事：**对齐时间与口径**（看单场环比还是周环比，GMV 是拍下口径还是成交剔除退款）；**拆公式**（GMV ≈ 进店 uv × 转化 × 客单价，或从曝光→点击→进店→下单逐层漏斗）；**定位是哪一环跌了**。再结合直播业务流程：**播前**（预热、预约、选品库存与佣金机制）；**播中**（流量结构是自然还是付费、停留与互动、上车讲解节奏）；**播后**（退款率、差评、风控处罚）。确认假设后再拉和小二权限一致的数据或跟播纪要，而不是只泛泛谈「选品不好」。

**问题：** 追问：有哪些环节、哪些因素？各环节可能出什么问题？

**答案：**  
**环节：** 招商选品 → 排期预热 → 开播引流 → 场内转化 → 履约售后 → 复盘迭代。  
**因素与典型问题：**  
- 播前：爆款缺货、机制重复乏力、预热短视频投放不足导致进场人数低。  
- 播中：付费投放缩减或 ROI 变差；话术平淡导致停留低；商品讲解顺序不合理导致点击进店低；优惠券 / 上车链路卡顿导致下单转化掉。  
- 商品侧：价格力弱、差评多、发货慢引发退款。  
- 平台侧：违规限流、类目管控、差评舆情导致隐性流量损失。  
每一步都可以落到「对应看什么指标、和谁对齐」。

**问题：** 介绍一下 AI Agent 项目（按背景、目标、遇到的困难、如何解决顺序）。

**答案：**  
**背景：** 研究所里分析师和量化同事有大量「资料收集 → 多角度解读 → 形成观点」的重复劳动，且结论最好有多视角校验。  
**目标：** 用多 Agent 分工并行生成基本面 / 技术面 / 情绪面要点，再通过「对立辩论」类 Agent 模拟多空讨论，最后由一个汇总 Agent 输出可读结论与引用线索，分析师把时间花在终审与决策上。  
**困难：** 模型易发散、上下文一长事实性变差；早期窗口有限；业务人员对 AI 不信任或使用不规范导致体感提效不明显。  
**解决：** 收窄任务边界（只做既定模板输出）、强约束 Prompt 与示例、结构化中间结果（表格 / JSON）便于复核；检索与数据库结论先行，生成只做解释；推广内部 Cursor / Cloud Code 等工作流和提示词模板，让团队风格一致；关键结论强制人工确认不上自动交易。

---

**问题：** 追问：信息获取是爬外网还是自有知识库？

**答案：** 结构化行情与指标主要来自所内金融数据库；文本类（研报摘要、公告要点）会在合规前提下爬取或接入供应商数据，再抽取入库；不会完全依赖模型「凭空回忆」。落地达人场景同理：**优先内部工单 / 规则库 / 经营数据**，外网仅作补充且要有合规边界。

---

**问题：** 是否做过数据源或知识库的整体梳理，还是以现成数据筛选为主？

**答案：** 两方面都有：**基建侧**要理清权威数据源、更新频率、字段口径和权限，否则后面因子和报表会对不齐；**应用侧**多数一开始是在现成库里做筛选和聚合，快速验证价值，再回头推动缺失字段或文档入库。知识库要配套版本与审核，否则 AI 会学到过期规则。

---

**问题：** 追问：重点工作是否在把控 AI 输出效果？

**答案：** 是的，对内落地时核心之一就是 **效果与安全**：输出格式是否稳定、事实是否可溯源、幻觉率和 Bad Case 是否可接受、有无合规风险；同时要做运营推广（怎么用、何时必须人工确认）。产品是「效果指标 + 协作流程」一起设计，而不是只堆模型。

---

**问题：** 如何判断 AI 解法好坏、是否需要改进？如何做评估？

**答案：** 先定义任务类型：若是 **整理 / 分类 / 草稿**，就看准确率、召回、人工修改幅度、平均耗时、一线满意度；若是 **决策辅助**，要看与人一致性抽检、事后复盘对错、是否带来业务指标改善（且注意混杂因子）。迭代触发条件包括：Bad Case 集中在某类意图、知识库缺失导致胡答、采纳率掉、转人工率异常升高。每周固定复盘样本和标注闭环。

**问题：** 追问：能对外推广使用的标准是什么？基于该标准有哪些过程指标？

**答案：**  
**准入标准（示例）：** 覆盖头部高频场景；抽检事实错误率低于团队阈值；关键结论可引用来源或工单 ID；灰度期无重大投诉 / 资损 / 合规事件；有回滚与人工兜底。  
**过程指标：** 自动解决率或命中率、**采纳率**、人均处理时长、转人工率、Bad Case 闭环时效、知识库命中率（命中仍答错说明生成有问题）、调用成本与 ROI。

**问题：** 追问：在「给分析师的洞察」方向上，输出好坏如何评估（而非仅资料整理）？

**答案：** 分和两层：**相关性**（洞察是否回答了当下决策问题，有没有漏关键矛盾）；**可验证性**（能否回到数据或文献佐证）；**可操作性**（下一步建议是清晰还是空话）。量化上可以抽样做「与人结论一致性」、跟踪分析师是否采纳某条洞见进入报告或因子池；在量化场景里还可以走样本外回测或小规模仿真，但必须声明假设与过拟合风险。达人侧则类比「诊断建议是否带来后续 GMV / 转化改善」，可用 AB 或对照组谨慎表述。

**问题：** 项目中遇到的最大困难是什么？

**答案：** 可以是「模型发散 + 上下文变长后质量滑坡」「业务不信任导致落地慢」「边界不清想要大而全」任选其一讲透。示例：**边界与可控性**最难——一开始需求表述宽泛，Agent 输出看似热闹但不稳定；同时上下文窗口和工具编排不成熟时，越复杂的链路越容易错一步全盘失真。

**问题：** 追问：你是怎么解决的？

**答案：** 收窄场景做成模板化输出；结构化中间结果方便核对；提示词与负面约束迭代；检索增强减少幻觉；人设上强制「不确定就列出缺失数据」；对内培训统一工具和 Prompt；高风险环节只出草稿由人签发。产品上预留 Bad Case 反馈入口推动知识库修订。

---

**问题：** 达人 B 端服务对象是小二与达人，很多事非标；你怎么理解小二的日常工作？

**答案：** 达人侧小二不只是「答疑客服」，更是 **生态运营界面**：达人分层维护（头部关系与潜力孵化）、招商撮合与活动档期协调、规则与处罚的解释申诉、经营数据复盘与改进建议、对内协同算法 / 治理 / 商家运营。很多工作是 **关系 + 流程 + 例外处理**，产品要做的是把高频、可标准化的部分沉淀成工单、知识库、报表和 AI 草稿，让人专注在高判断环节。

---

**问题：** 开放题：若让你做一个 AI 产品帮助业务，你会做什么（可多方向）？

**答案：** 可以说三个并列方向：① **规则与政策问答（RAG）**，小二 / 达人高频咨询一键溯源；② **工单 / IM 辅助**：自动分类、摘要、回复草稿，降低平均响应时长；③ **经营诊断摘要**：直播后自动生成「流量结构 + 转化漏斗 + 退款舆情」备忘录，减少手工 Excel。强调先做高频闭环 MVP，再扩展。

---

**问题：** 追问：中小达人可做智能客服；对头部达人（需小二 1 对 1），你会设计哪些 AI 产品帮小二提效？

**答案：** 头部重在 **关系维护与复杂博弈**，AI 可做：**跟进助手**（每日异动、待办、风险提示）、**沟通草稿**（基于达人画像与历史纪要生成话术建议，人工发送）、**选品与机制备选清单**（对标历史带货与同类达人表现）、**复盘纪要**（场次摘要与流失节点）。原则是不代替小二决策，只压缩信息整理与草稿时间。

---

**问题：** 追问：不同人不同风格，如何标准化？如何收集这些信息？

**答案：** 标准化的是 **SOP 骨架与知识资产**，不是消灭个人风格：同一跟进流程里必填字段一致，话术保留「变量槽位」。收集方式：**跟岗脱敏样本**、CRM / IM 高频问答与高分回复库、工单标签、资深小二结构化访谈与复盘会。落地为分层知识库（通用规则 / 类目 playbook / 达人个性化备注）+ 模板 + AI 填空；质检看必填项与合规，不评判文风。

**问题：** 反问环节：你可以向面试官提什么问题？

**答案：** 本题没有唯一答案，以下为可直接用的话术示例（选 1～2 个）：① 团队当前达人侧产品优先级最高的一件事是什么？② 实习生前三周期望产出什么（文档 / 跟岗 / 小需求）？③ AI 产品在内部推到一线的阻力通常在哪（数据、合规还是采纳）？④ 考核实习生时最看重的 signal 是什么？⑤ 团队规模和协作节奏（与运营 / 研发配比）。避免只问「我表现怎么样」——若问，可以补充「您认为我最该补的一块业务知识是什么」。

**问题：** 面试官当场给的反馈（例如希望你讲得更细），你怎么理解和回应？

**答案：** 这不是打分题，而是 **收尾表态**：感谢具体建议（例如希望听到环节级拆解），承认自己有时会偏方法论，下次会用「环节清单 + 典型问题 + 验证方式」来表达；表达愿意在实习里多跟岗把颗粒度练出来。简短、诚恳即可。

**问题：** 是否已在读研究生 / 录取状态？

**答案：** 按事实回答即可。示例（与转写一致）：已被电子科技大学拟录取，尚未入学 / 处于入学前空档；因此实习时间上可以全勤（勿编造，若已开学则如实说明每周可出勤天数）。

**问题：** 若可以实习，一周能来几天？不需要上课吗？

**答案：** 按事实回答：例如当前 gap 期可 **每周 5 天**；若入学后以校方课程为准再协商 **不少于 X 天**。核心是 **诚实 + 可协商**，避免承诺无法兑现的天数。
